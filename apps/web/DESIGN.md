# Design System: ПоРукам — торговая витрина

## Overview

**Creative North Star: "Понятная торговая витрина"**

Понятная торговая витрина соединяет почти белую голубоватую сцену, настоящие белые карточки, тёмные чернила и синие действия. Плотная композиция помогает сразу увидеть товар и цену; объёмная оптика остаётся локальным свойством ключевых кнопок. Исходные цвета логотипа и изображений товаров сохраняются.

Визуальная власть принадлежит пользовательскому [макету](.impeccable/references/approved-storefront.png); его воспроизведение прямо запрошено пользователем. Предыдущая серебристая сцена заменена. Тёмная тема даёт полный чернильный аналог шапки, поиска, меню, карточек и форм. Контракт композиции хранится в [market.md](.impeccable/surfaces/market.md); продуктовые ограничения — в [PRODUCT.md](PRODUCT.md), с приоритетом его последней коррекции.

**Key Characteristics:**

- Почти белый фон, белые карточки, компактная шапка и сдержанные синие действия.
- Локальный кириллический Manrope, короткое название, заметная точная цена и явная единица.
- Отдельные кнопки категорий и мягкое увеличение переключателей1.025/180ms при наведении мышью; оптика ключевых действий изгибается отдельно от текста и области нажатия.

- Правые иллюстрации справки — самостоятельные 3D-модели с поворотом за мышью; первый кадр берётся из текущей сцены, без смены прежней картинки на модель.

## Colors

Нормативные RGB-значения frontmatter извлечены из последнего блока темы в `app/design.css`; он переопределяет `app/globals.css`. Префикс `dark-` обозначает значение той же роли в тёмной теме. Метаданные цветовых полос в sidecar служат предпросмотру; они не расширяют палитру приложения.

### Primary

- **Чернильный синий** (`primary`, `primary-hover`, `on-primary`): основное действие; в тёмной теме действие становится светлым с тёмной надписью.
- **Бледный голубой выбор** (`primary-soft`): выбранные разделы и категории.

### Neutral

- **Почти белая сцена** (`scene`, `bg`, `bg-accent`): фон и вложенные рабочие области.
- **Белая карточка** (`surface`, `surface-raised`): товар, меню, поле поиска и панель формы.
- **Тёмные чернила** (`text`, `text-muted`): основное содержание и пояснения.
- **Холодная граница** (`border`, `glass-edge`): тонкий контур отдельной поверхности.
- **Светлая шапка** (`glass-header`): почти непрозрачная непрерывная подложка.
- **Поле и раскрытие** (`field-bg`, `picker-bg`, `picker-solid`): редактирование и нативное меню выбора.

Семантические пары `danger`, `success`, `warning` и мягкие подложки обозначают ошибку, подтверждение и предупреждение. Цвет всегда сопровождается содержательным текстом. Зелёная отметка производителя допустима только при подтверждённом источнике: публичный каталог допускает компании через серверный `admission.py`.

**The Reference Authority Rule.** Воспроизводить утверждённый пользовательский макет; фактические категории, цены, изображения и статусы брать из текущего API.

## Typography

**Display Font / Body Font:** локальный Manrope Variable (вес 200–800), затем Segoe UI и системный sans-serif. Источник — `app/fonts/Manrope-variable.ttf`, подключённый через `next/font/local`. Encode Sans не поставляется: оценка похожести шрифта не является источником токенов.

Крупный плотный заголовок и короткие рабочие подписи воспроизводят ритм макета. Точные значения ролей заданы в frontmatter. Основной текст остаётся читаемым, а цены используют табличные цифры.

- **Display:** заголовок складского баннера; на ширине до 1000px — 45px, до 760px — 36px, до 360px — 32px. На десктопе свыше 1000px исходный CSS сжимает только заголовок по X до .92; кнопки и карточки этого преобразования не получают.
- **Headline:** название раздела и завершающая запросная полоса; на мобильном заголовок каталога — 21px.
- **Product title:** одна строка на десктопе; на мобильном две строки (13px, line-height 1.35, минимальная высота 35px).
- **Price:** заметный вес и табличные цифры; на мобильном 20px, до 360px — 18px. Единица выводится отдельно из характеристик товара.
- **Body / prose / help:** операционные и читаемые поверхности. Поясняющий текст ограничивается 70–75ch там, где это задано компонентом.
- **Navigation:** компактные подписи; белый фон и интервалы поддерживают считывание без прописных букв.

## Layout

Контейнер ограничен 1600px; основной горизонтальный отступ — `clamp(35px,2.73vw,44px)`, до 1000px — 24px, до 760px — 14px, до 360px — 10px. Базовый вертикальный зазор витрины — 14px, между категориями и результатами — 20px. Композиция первого экрана, складской баннер и нижняя полоса принадлежат контракту рынка, а не обязательной структуре каждой рабочей страницы.

Непрерывная липкая шапка имеет высоту `clamp(62px,4.84vw,70px)`. На мобильном она перестраивается в строки бренда/аккаунта, поиска и разделов. При ширине до 1000px поиск имеет итоговую высоту 48px, поле и кнопка отправки — 44px; это позднее переопределение важнее раннего мобильного правила 44/36px. На десктопе поиск 42px, поле и отправка — 36px.

Сетка товаров: четыре колонки свыше 1000px, три до 1000px, две до 760px. Десктопный зазор 14px; мобильный — 12px по вертикали и 10px по горизонтали. Категории — отдельные кнопки с горизонтальной прокруткой, а не общая стеклянная панель. Домашний экран сначала выводит четыре фактических предложения; «Показать ещё» раскрывает дополнительные товары. По умолчанию выбран пункт «По популярности»: сервер ранжирует товары по числу закупок с положительной подтверждённой приёмкой за вычетом возвратов. Главная и каталог сохраняют этот порядок при поиске и выборе категории; «По названию» включает алфавитную сортировку. Значения рейтинга и фиктивные продажи не показываются.

## Elevation & Depth

Основная сцена статична; белые карточки отделены тонким контуром и слабой тенью. Выраженная оптика ограничена ключевыми действиями: поиск, потребность в баннере и завершающая потребность. Отдельные справочные поверхности сохраняют две различные формы: мягкую линзу помощи и более прямоугольную пластину закупок с асимметричным нижним углом. Это не материал всех панелей и карточек.

Точные тени, фокус и движение находятся в sidecar `extensions`: малая тень обозначает карточку, средняя — меню и диалог, внешняя оптическая — оболочку. При готовой WebGL-сетке CSS оставляет только заливку и внешнюю тень, чтобы не удваивать кромку.

У объёмных оболочек запас вокруг canvas составляет от 8 до 32px и помещается в доступное расстояние до края viewport. Проецируемое смещение плавно ограничено значением `min(24px, gutter − 6px)`, включая выброс пружины; это сохраняет прозрачный запас у границы GPU и предотвращает резкое отсечение справа. На узких экранах изгиб мягче. Размер буфера по-прежнему не больше 1100×600, без умножения на DPR.

Категории — плотные объёмные кнопки с небольшой фаской и мягкой нижней тенью. У них нет liquid-материала, canvas, WebGL или реакции формы на положение курсора. На точной мыши hover плавно увеличивает всю кнопку до1.025 за180ms с существующим `--ease-out`; нажатие —1.005 за100ms. Нативная прокрутка сохранена, вокруг кнопок оставлен запас для увеличения. На touch и при reduced motion масштабирование отключено.

Fine-pointer отклик использует ограниченную пружину (масса 1, жёсткость 100, демпфирование 10) и останавливается после успокоения. Нет постоянного idle-цикла. Скрытая вкладка, потеря фокуса и уход поверхности за экран прекращают расчёт. Touch/coarse pointer, reduced motion, reduced transparency, forced colors, отсутствие WebGL и потеря контекста оставляют статическую CSS-оболочку; после восстановления контекста сетка пересоздаётся. В forced colors остаются системные границы и цвета.

**The Stable Content Rule.** Деформируется только декоративная оболочка: надпись, текст, ссылка и область нажатия остаются неподвижны.

## Shapes

Узкие контуры и умеренные углы задают рабочую геометрию. Точные радиусы заданы в frontmatter. Карточка имеет небольшую кромку (3px; на мобильном 2px), изображение — верхние скругления, поле — самостоятельный контур. Изображение карточки сейчас имеет отношение сторон 1.546 на десктопе и 1.2 на мобильном, `object-fit: contain`; старое требование квадратного изображения не описывает текущий макет.

Сегментированные разделы и поиск вытянуты по горизонтали. Формы помощи и закупок различаются: мягкая линза и пластина с асимметричным нижним углом; на мобильном их радиусы сокращаются до 32px и `22px 22px 42px 22px` соответственно. Логотип остаётся оригинальным изображением без фильтров и маскирования.

## Components

### Buttons

Основная рабочая кнопка — уверенная синяя заливка; hover использует `primary-hover`, фокус — видимый контур. Вторичная — светлая подложка с холодной границей и `primary-soft` при наведении. Обычные рабочие кнопки при нажатии используют `translateY(1px) scale(.98)`; это не применяется к неподвижной надписи внутри liquid-действия. Неактивное действие приглушено и имеет курсор запрета. Три действия справочных hero («Создать потребность» в ИИ, «Создать потребность» и «Написать в поддержку» в помощи) используют общий toggle-motion: hover1.025/180ms, press1.005/100ms; touch/reduced motion остаются статичны.

Liquid-действия содержат отдельные материальный слой и декоративный canvas. Синий вариант служит отправке и созданию потребности, контурный — действию баннера. Самостоятельные HTML/CSS-примеры sidecar показывают статический fallback; они не имитируют WebGL или бизнес-логику.

### Guidance 3D objects

Правые иллюстрации `/ai-procurement` и `/knowledge` имеют оригинальные процедурные Three.js-модели: плотный трёхлопастный узел из широкой ленты со стеклянными гранями и узкой хромированной кромкой и композицию планшета с тремя отметками, коробкой и сообщением. Это объёмные сетки с боковыми поверхностями, фасками и освещением, а не поворот прямоугольной картинки. Формы стилизованы по прежним иллюстрациям; скрытые стороны достроены. Палитра — ледяной хром, синий и кремовый, без внешних текстур/HDRI. Оптика существующего hero работает отдельно, контент и действия неподвижны.

Мышь задаёт поворот по X±0.32, Y±0.6 и Z±0.07rad. Экспоненциальное сглаживание с постоянной95ms, без линейного движения и циклического idle-вращения; уход/отмена указателя и потеря фокуса возвращают модель. Объём вписывается по реальным вершинам с запасом. RAF останавливается после достижения цели; текстуры, геометрия, материалы, observers/listeners освобождаются. Отдельный chunk загружается только для видимого объекта при разрешённом движении; буфер не больше640×640, DPR≤1.6. Первый HTML-кадр и статичные режимы используют PNG-кадр из той же текущей сцены: совпадают геометрия, камера, поза и свет; для обеих тем свои кадры. Старые business-link.webp/procurement-help.webp не подключаются. На touch/reduced motion/transparency/без WebGL2/при потере контекста остаётся этот же вид модели; при forced colors декорация скрыта. Смена темы обновляет свет, восстановление контекста пересоздаёт сцену. Первый кадр резервирует геометрию без сдвига раскладки. Регенерация четырёх PNG: scripts/render-hero-posters.mjs с адресом локального preview; PNG экспортируется прямо из WebGL до очистки буфера, рядом сохраняются хэши исходников и файла. У AI физическое стекло: transmission.58, IOR1.48, thickness.52, dispersion.12, iridescence.22; четыре студийных softbox и тёмное отражающее окружение. Это PBR с объёмным пропусканием/преломлением и PMREM-отражениями, не path tracing. Модель и свет помощи сохранены. Экспоненциальное сглаживание использует фактическое время между кадрами без искусственного замедления при низком FPS.

### Inputs / Fields

Поля имеют явную подпись, спокойный фон и контур; focus меняет границу и добавляет кольцо. Поиск — единая горизонтальная форма с настоящей кнопкой отправки и доступным названием. Нативные select/option используют текущую тему; расширенное оформление `base-select` применяется только при поддержке браузером. Остальные браузеры сохраняют доступный системный выбор.

### Navigation

Переключатели разделов, режимов, темы, избранного и раскрывающие элементы используют то же мягкое увеличение, что категории: scale(1.025), 180ms ease-out; нажатие — scale(1.005), 100ms. Переход прерываемый, без JS и liquid-материала. Эффект включён только для мыши с fine pointer, отключён при reduced motion и у недоступных контролов. Семантика, клавиатурный фокус и размеры раскладки сохраняются.

Два сегмента рынка обозначают маршруты «Товары» и «Потребности». Выбранный сегмент получает голубую подложку; внешние рабочие ссылки остаются компактными текстовыми действиями. При сужении служебная навигация раскрывается через меню; маршруты и роль аккаунта сохраняются. Клавиатурный фокус (2px с отступом 4px) и ссылка пропуска к содержимому обязательны.

### Categories

Иконка и русское название находятся внутри отдельной кнопки; выбранное состояние передаётся через `aria-pressed`, голубую подложку и более плотный вес. Список происходит из реально доступных категорий API; образцовые категории картинки не дописываются как пустые разделы.

### Cards / Containers

Белая карточка объединяет изображение, короткое название, точную цену с единицей и статус производителя. Нет подъёма или увеличения изображения при hover. Изображение поступает из текущего хранилища; отсутствие фотографии обозначено явно, иллюстрация сохраняет подпись «Иллюстрация». Метка производителя подтверждается допуском публичного каталога, а не внешним видом карточки. Минимальный объём показывается в каждой карточке, включая карточки проверенных производителей.

Избранное — настоящая кнопка с областью 44×44px и `aria-pressed`. Подсказка сообщает о сохранении в текущем браузере; при недоступном localStorage остаётся состояние текущего сеанса. Общая ссылка карточки и кнопка избранного являются отдельными интерактивными элементами.

### States

Загрузка показывает спокойные скелеты без постоянной анимации. Ошибка предлагает повторить запрос, пустая выборка — изменить поиск/категорию или создать потребность. Состояние загрузки и количество предложений доступны через `role="status"`; ошибка — через `role="alert"`. Визуальные изменения не подменяют эти бизнес-состояния фиктивными товарами.

## Do's and Don'ts

### Do:

- **Do** сохранять исходные цвета логотипа и товаров и использовать предоставленный складской материал.
- **Do** показывать фактические цену, единицу, категорию и статус доступного предложения.
- **Do** сохранять обе темы, клавиатурный фокус и статическую замену оптики.
- **Do** оставлять отдельные кнопки категорий и плотную сетку с адаптацией к ширине.

### Don't:

- **Don't** возвращать отвергнутую серебристую сцену, водяной след, фоновый параллакс или фоновую анимацию.
- **Don't** придумывать популярность, коммерческие показатели, email или подтверждение производителя.
- **Don't** переносить образцовые товары и цены из картинки вместо фактических данных.
- **Don't** заменять поставляемый Manrope шрифтом Encode Sans по предположению автоматического сопоставления.
- **Don't** искажать текст или изображения карточек при наведении.

Извлечение основано на текущих `app/design.css`, `app/globals.css`, `app/layout.tsx`, `ProductCatalog`, `ProductCard`, `SiteNavigation`, `LiquidSurface` и `liquidGlassMesh`. Пользовательский макет просмотрен; эта документация не заявляет измеренный pixelmatch или полное пиксельное совпадение. Геометрия, шрифт и товарные данные в реализации проверяются отдельно от документирования.

## Совместимость и проверка на устройствах

Сопоставление девяти пользовательских снимков и записи экрана, инструкция для агента на Mac: [mac-safari.md](../../docs/troubleshooting/mac-safari.md). Цвет в shader сразу умножается на прозрачность, контекст использует premultiplied alpha; дополнительное преобразование непрозрачного RGB при композиции не требуется ([контракт WebGL](https://registry.khronos.org/webgl/specs/latest/1.0/#WEBGLCONTEXTATTRIBUTES)). До показа canvas проверяется реальный framebuffer в обеих темах, в покое и при противоположных изгибах. Проверка повторяется после смены темы/размера, при входе указателя и завершении движения; в покое и на каждом pointermove пиксели не читаются. Непрозрачная полоса или пустой кадр оставляют CSS-материал с лёгким наклоном до 1,2° за мышью. Текст и области нажатия неподвижны. Touch, reduced motion/transparency и forced colors сохраняют статичный вариант; самостоятельные 3D-модели не отключаются.

Все отображаемые даты используют `lib/dates.ts`: календарные — `дд.мм.гг`, события — та же дата с временем. `DateInput` показывает русский календарь независимо от языка браузера; в состоянии формы/API сохраняется ISO. Имена, исходные документы и технические реквизиты не переписываются. В карточках сверху указан статус склада по свежим данным продавца, цена «от» и минимальная партия «От …»; статус не означает резервирование объёма. Иконки категорий в тёмной теме используют светлый токен primary.

Один дизайн используется во всех браузерах. Для Safari заданы префиксные варианты backdrop-filter и mask-image. Декоративная WebGL-оболочка требует достаточной точности fragment shader; если её нет, остаётся CSS-материал. Формула отражения не использует `pow` с отрицательным основанием: такое вычисление не определено спецификацией GLSL и может давать разный результат на разных GPU. Источник: [спецификация GLSL](https://registry.khronos.org/OpenGL/specs/es/3.2/GLSL_ES_Specification_3.20.html).

На touch-устройствах сохраняются статические материалы и постеры 3D-сцен, без реакции на несуществующее наведение мыши. Поля используют шрифт не меньше 16px; основные компактные переключатели и иконки имеют область нажатия не меньше 44px. Выемки экрана учитываются через safe-area, высота панели аккаунта — через динамический viewport. Масштабирование страницы пользователем разрешено.

Вложения черновика сохраняются локально в IndexedDB как байты и метаданные, затем восстанавливаются в File. Запись микрофона выбирает доступный MIME-тип; MP4 получает расширение `.m4a`. Требуется разрешение на микрофон и защищённое соединение HTTPS (localhost допустим при локальной разработке). При недоступной записи можно приложить готовый файл.

### Автоматическая проверка

Матрица `tests/e2e/compatibility-browser.config.ts`: настольные Chromium и WebKit, iPhone и iPad на WebKit, Android на Chromium. Проверяются обе темы, каталог, поиск, сортировка, избранное, справочные страницы, панель аккаунта, портретная и альбомная ориентация, формы и вложения. Отдельный тест проверяет MP4-запись через подменённый MediaRecorder; это проверка обработки формата, а не физического микрофона. Тест GPU-отражения выполняется только при наличии WebGL с достаточной точностью; пропуск отображается явно.

Перед запуском собрать web с публичными путями того же origin: `NEXT_PUBLIC_API_URL=/gateway NEXT_PUBLIC_MARKETPLACE_URL=/marketplace NEXT_PUBLIC_LLM_GATEWAY_URL=/llm pnpm build:web`. Затем из `tests/e2e` выполнить `pnpm exec playwright install --with-deps chromium webkit` и `pnpm exec playwright test --config compatibility-browser.config.ts`. API в этих сценариях перехвачены синтетическими ответами; это не проверка работающих backend-сервисов.

Эмуляция размера и ввода не воспроизводит Apple GPU/Metal, системный микрофон и производительность реального телефона. WebKit на Linux также не является установленным Safari на macOS: [ограничения движков Playwright](https://playwright.dev/docs/browsers). Окончательная проверка конкретного MacBook проводится на самом устройстве.

### Если на MacBook всё ещё искажаются рамки

1. Открыть адрес сборки, в которую вошли изменения PR #155. До слияния PR обычный адрес основной ветки может показывать предыдущий дизайн. Сравнивать одну и ту же сборку и страницу на обоих компьютерах. Для доступа со второго устройства использовать [HTTPS-профиль из README](../../README.md#другие-устройства-и-https): `localhost` на телефоне или другом Mac указывает на само это устройство, а не на компьютер разработчика. Сертификат должен быть доверенным; API доступны через тот же адрес сайта.
2. Записать версию Safari из меню «Safari → О Safari», версию macOS и модель/чип из «Об этом Mac». Сбросить только масштаб страницы сочетанием `⌘0`; оставить системные настройки экрана без изменений.
3. Перезагрузить страницу. Если остаются признаки старой сборки, включить инструменты разработчика в «Safari → Настройки → Дополнения» (пункт показа функций для веб-разработчиков), затем выбрать «Разработка → Очистить кэши» и обновить страницу. Названия могут различаться с языком и версией Safari; см. [включение инструментов](https://developer.apple.com/documentation/safari-developer-tools/enabling-developer-features) и [меню Develop](https://developer.apple.com/documentation/safari-developer-tools/develop-menu). **Не удалять данные сайта, IndexedDB или историю:** там могут находиться несохранённые черновики и вложения.
4. Проверить главную, каталог, «ИИ-закупки» и «Поддержку» в обеих темах. На Mac провести мышью вдоль правой и левой кромки объёмной рамки и убрать курсор. Проверить, что надписи не деформируются, кромка не исчезает и клики работают. На iPhone/iPad дополнительно повернуть устройство и открыть панель аккаунта; статичный материал на touch — ожидаемое поведение.
5. Если дефект сохраняется, сделать снимок окна с проблемной кромкой, указать страницу, тему, масштаб и размер окна. Скрыть персональные и коммерческие данные. Для диагностики открыть Web Inspector (`⌥⌘I`), вкладку Console и выполнить приведённый ниже код. Он читает только возможности браузера и геометрию окна; не читает токены, документы, содержимое форм и хранилища.

```js
(() => {
  const canvas = document.createElement('canvas');
  const gl = canvas.getContext('webgl');
  const precision = gl?.getShaderPrecisionFormat(gl.FRAGMENT_SHADER, gl.HIGH_FLOAT);
  const result = {
    browser: navigator.userAgent,
    viewport: [innerWidth, innerHeight],
    dpr: devicePixelRatio,
    backdrop: CSS.supports('backdrop-filter', 'blur(1px)'),
    webkitBackdrop: CSS.supports('-webkit-backdrop-filter', 'blur(1px)'),
    mask: CSS.supports('mask-image', 'linear-gradient(black, transparent)'),
    webkitMask: CSS.supports('-webkit-mask-image', 'linear-gradient(black, transparent)'),
    webgl: !!gl,
    highp: precision && { bits: precision.precision, rangeMax: precision.rangeMax },
    glass: [...document.querySelectorAll('.liquid-surface__mesh')].map(c => ({
      ready: c.dataset.ready ?? false, width: c.width, height: c.height,
      fallback: c.parentElement?.dataset.glassFallback ?? null,
    })),
    reducedMotion: matchMedia('(prefers-reduced-motion: reduce)').matches,
    coarsePointer: matchMedia('(pointer: coarse)').matches,
  };
  gl?.getExtension('WEBGL_lose_context')?.loseContext();
  return JSON.stringify(result, null, 2);
})();
```

6. Передать результат и снимок для воспроизведения. Не отключать защиту Safari, CORS, WebGL или экспериментальные настройки ради сайта. Отдельная версия дизайна для одного устройства не требуется: исправление должно учитывать возможности браузера и сохранять рабочие сценарии у остальных пользователей.
