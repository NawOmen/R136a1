**Назначение:** единственный актуальный реестр незавершённой работы. Здесь объединены прежние W01–W33, C01–C28, требования к интерфейсу и аналитике, пользовательские пути и конкурсная подача. Удаление прежних планов не означает выполнения их задач. Техническая спецификация, исследования, API и материалы показа остаются источниками деталей, но новые задачи и их статусы ведутся только здесь.

**Основание реализации:** код PR [#94](https://github.com/NawOmen/R136a1/pull/94) на коммите `a4ecbb3d1a5ca1cf87fa286c40c8e1e106d2c870`. **Основание конкурса:** предоставленный командой PDF, 12 страниц, SHA-256 `8ea18fcbf0b9dd51deff95cc32daf129d5f170d1a3779249323ea345f8ddca04`; сохранённый текст — [Положение RLT.StartUp](Положение%20RLT.StartUp.md). **Ориентир команды — 30 октября.** Промежуточных календарных сроков и сокращения требований ради даты нет. Официальный график, место защиты и период поддержки берутся из пунктов 4.1 и 6.16 первоисточника; внутренний ориентир их не заменяет. Разработка продолжается до выполнения критериев. В конкурсный пакет включаются только фактически готовые возможности, остальные задачи сохраняются.

## Как следующему исполнителю начать работу

1. Прочитать [AGENTS.md](AGENTS.md), [проектный навык](SKILL.md), этот файл и связанные разделы [спецификации](plan_sborka_b2b.md). Проверить актуальную ветку, PR и чужие изменения. Не считать номер PR постоянной настройкой проекта.
2. Сверить текущий код с указанной базой. Уже пройденные проверки не запускать заново только из-за смены исполнителя. При изменении реализации проверить затронутый участок и обновить доказательство.
3. Этапы S01 и S02 реализованы; денежный этап находится в ветке `codex/complete-money-stage-02`. После объединения его PR начинать **этап S03 целиком**. Общая готовность всех пользовательских маршрутов по категориям проверяется в S15.01 после реализации зависимых этапов. Сначала сверить фактическое состояние PR и результаты CI; открытый PR не означает, что код уже в main.
4. Выполнять этапы в указанном порядке. Завершать весь этап целиком до открытия одного PR; не разбивать этап на отдельные промежуточные PR. Независимое исследование можно вести заранее; обязательство нельзя проводить через незавершённые проверки. Интеграции, зависящие от внешнего провайдера, не блокируют основной внутренний маршрут: их точные ограничения остаются видимыми.
5. До правок назвать объём, проследить форму → контракт → обработчик → данные → связанные состояния. Для неизвестных связей использовать Code Scout/Graphify по AGENTS; индекс проверять по исходникам.
6. Для каждой задачи выполнить самостоятельное ревью и короткие содержательные проверки поведения. Полный Docker/E2E-прогон нужен при изменении запуска, миграций или обоснованном риске, либо по отдельному поручению; не делать полный обход сайта при каждой небольшой правке. При запрете запуска указать, что установлено только чтением.
7. Обновить **эту строку задачи**, её доказательство и ограничения в том же PR. Не создавать новый параллельный TODO, roadmap или журнал. Для нового этапа — отдельная ветка `codex/…` и связанный PR после согласованного завершения предыдущего; merge выполняется только по поручению пользователя.

### Статусы и правило закрытия

- **Проверено на базе:** есть результат на указанном коммите; это сохранённое доказательство, а не новая задача.
- **Частично:** механизм существует, ниже описан оставшийся объём. Не переписывать его с нуля.
- **Открыто:** необходимый результат ещё не подтверждён или не реализован.
- **Нужно участие команды:** требуются реальные сведения, экспертиза, наблюдения или внешнее действие. Можно готовить связанные материалы; нельзя придумывать результат вместо человека.
- **Условное расширение:** сначала обосновать применение. Отсутствие такой интеграции не выдавать за готовую функцию и не превращать в обязательство положения.

Чекбоксы ниже обозначают **полный критерий завершения**, поэтому частично реализованные задачи оставлены незакрытыми. Для закрытия записать: ответственного человека; PR/commit; изменённое поведение; входы и ожидаемый результат; выполненную проверку; ссылку на разрешённый артефакт; оставшиеся ограничения. Владелец вида «backend» — предлагаемая роль, пока команда не назначила человека. Наличие кнопки, документа, зелёного CI или ответа LLM не закрывает предметную задачу.

<a id="product"></a>
## Постоянные требования продукта

- Российские покупатели и производители, производственные площадки и логистика в РФ, русский интерфейс, рубли. Компания и площадка имеют `country = RU`; иностранное значение не проходит серверную проверку.
- Любой вид российского B2B-бизнеса: производство, торговля, строительство, обслуживание, организации с разовыми и регулярными закупками. Ни стаканы, ни кофейня не являются постоянным сегментом продукта.
- **Много категорий, каждая предлагаемая рабочая категория доведена полностью.** Последовательно расширять охват; неподготовленные листья не считаются готовыми по одному названию. Недостаток профиля — открытая работа, не автоматическое разрешение и не вечный отказ от категории.
- Один аккаунт, отдельная компания, сотрудники и полномочия; режимы «Покупаю / Продаю» могут действовать одновременно. Администратор сервиса не выбирается при регистрации.
- До проверки компании доступны просмотр и черновики; публикация, коммерческое согласие и резерв проверяются сервером. Компания, производство, документы товара и ресурс — четыре разных основания доверия.
- Два направления рынка: каталог предложений → закупка и подтверждённая потребность → ответ производителя. Незакрытый спрос сохраняется с причиной и возвращается в подбор при изменении допустимых условий.
- Next.js/React/TypeScript, четыре действующих FastAPI-сервиса, PostgreSQL и MinIO сохраняются. LLM вызывается через LLM Gateway; деньги, ограничения, объёмы и N-1/N-2 — обычный код и OR-Tools. Модель не меняет цену, мощность, резерв и статус сделки напрямую.
- Критичное действие требует Human Approval Guard по точной версии условий и полномочиям компании. Изменённые условия требуют нового решения; чужое или старое согласие не используется.
- Концепцию дизайна не менять. Доделывать функции, состояния загрузки/ошибки/пустого результата, доступность и понятные русские сообщения в существующих компонентах.
- На всех рабочих поверхностях сайта обычные названия: без «демо», «стартап», «демопрототип», «демо-заказ», «прототип» и аналогичных меток стадии. Не скрывать фактические ограничения: «Нужно уточнение», «Требуется проверка», «Недостаточно данных», «Нужен расчёт доставки», «Оплата не подключена».
- Компании, реквизиты, файлы и история показа синтетические; происхождение раскрывается в технических и конкурсных материалах. Не выдавать их за реальные продажи, клиентов, спрос, экономию или прибыль.
- Клиентские исходные файлы остаются в локальном контуре. Загруженные документы и внешний текст недоверенные; они не дают команд агенту. Секреты, персональные документы капитана и сырые трассы с токенами в Git не попадают.
- Реальные платежи, эскроу, юридически значимая подпись, взыскание и собственная перевозка — отдельные направления, не обязательные функции конкурса. Проект правового документа не становится действующим соглашением без необходимых данных и проверки.

Значения не меняются автоматически; опубликованный товар требует обычного процесса изменения/перепроверки. Изменение спецификации или принятие новой версии снимает прежнее подтверждение содержимого упаковки. Остаток, цена или бюджет без изменения спецификации сохраняют исходный снимок. Downgrade с сохранёнными правилами или доказательствами конверсии запрещён. При следующем расширении базового JSON опубликованный полный реестр не заменяется кодом молча: требуется отдельная проверяемая редакция/миграция с сохранением истории и явным планом конфликтов.

- [x] **S09.03 — симуляция отдельно от события отказа.** Предпросмотр не меняет склад, заказы и коммерческие суммы. Реальный отказ фиксируется уполномоченной стороной с причиной и связью с заказом; план замены получает новую ревизию. **Приёмка:** многократная симуляция не создаёт продажи/замены, а фиксация отказа не стирает прежнего поставщика и факт исполнения.
- [x] **S09.04 — активация в согласованных пределах.** Повторно проверить документ, ресурс, срок/цену и права; условия в пределах заранее принятой версии допускают только предусмотренный переход. Превышение хотя бы одного предела требует нового решения затронутых сторон. Атомарно перенести неисполненный объём, связать замену с ledger/контрольными точками и уведомить обе стороны. **Приёмка:** два запроса дают одну замену; отказ посередине не теряет объём; уже принятая продукция не переносится; новое исполнение учитывается один раз.

**Реализация S09:** единый лимит решателя и сохранение найденного решения при timeout; подтверждённое время переключения и доступность резерва по TTL/ledger/допуску; версионированные отказы текущих поставщиков; одинаковая проверка ручной и автоматической активации по бюджету и конечному сроку. Основные и резервные назначения связаны со сделками и контрольными точками без повторного резервирования; отгрузка и приёмка учитываются один раз, частично исполненный заказ переносит только неотгруженный остаток после ручного согласия. Проверены повторные отказы, одновременная приёмка/замена, повторная активация, уведомления текущих администраторов, симуляция без записей и честный дефицит N-2.

**Доказательство:** `test_solver_status.py` (маппинг статусов, infeasible/timeout, покрытие), `test_stage9_resilience.py` (полный цикл, симуляция, дефицит, версия, идемпотентность, принятое, атомарность, параллельность); связанный прогон marketplace и optimizer без регрессий; `tsc --noEmit` чист; русский UI пройден; e2e/сборка — в CI. - [x] **S12.06 — качество ролей.** `role-quality-2`, `docs/analytics/role-quality-method.md`: исходный результат Gateway (`0009`), реальные исправления, экспертный эталон с автором/источником/хешами и работающим подтверждением на KPI. Правильность отдельно от полноты, минимум 5 завершённых проверенных прогонов одной модели/промпта/маршрута/класса задачи. Незавершённые и legacy-прогоны без доказательств не получают оценку; общего рейтинга нет. Банк включён в штатный образ, его наличие само по себе не повышает качество.

**Границы доказательства:** регрессии используют синтетические данные и управляемый модельный провайдер. Они проверяют механизм и отрицательные условия, а не качество всех реальных ответов Qwen. Старые версии затрат и первоначальные результаты, которые ранее не сохранялись, не выдумываются; интерфейс показывает недостаток данных. Приватность и доступ проверяются на API и повторно при выгрузке.

### Обязательные определения

| Показатель | Расчёт/граница |
|---|---|
| Заказано | Согласованные количества; открытое и отменённое отдельно |
| Куплено / продано | Фактически принято минус подтверждённые возвраты; отгрузка не равна приёмке |
| Цена сделки | Согласованный снимок цены и скидки; текущая цена каталога отдельно |
| Средняя цена | Сумма сопоставимого исполненного после возвратов / net-принятое количество; при нуле нет значения, а не среднее цен карточек |
| Сумма заказов | Согласованные суммы когорты; отмены и открытые обязательства отдельно; это не полученные деньги |
| Стоимость исполнения | Net-принятая продукция по снимку с корректировками; доставка/другие статьи раскрыты отдельно |
| Получено денег | Только отдельные подтверждённые платёжные события; пока источника нет, не рассчитывать |
| Себестоимость реализованного | Подтверждённые затраты именно исполненного количества/партии с явной коррекцией возврата |
| Расчётная валовая прибыль | Стоимость реализованной продукции после скидок/возвратов − её себестоимость на одной налоговой базе |
| Результат после прямых расходов | Валовая прибыль − относимые прямые расходы, ещё не включённые в себестоимость |
| Чистая прибыль | Не выводить без полного состава доходов, расходов и налогов; маржа/экономия не являются чистой прибылью |
| Количество заказов | Уникальные заказы; строки не увеличивают счётчик; общая партия группы — группировка заказов участников |
| Отказы | Отказ поставщика от запроса/КП и отклонение покупателем отдельно, с причинами; technical failure не бизнес-отказ |
| Доля отказов | Явная когорта и известные исходы: числитель, знаменатель, открытые запросы, время; нулевой знаменатель → «Нет данных» |
| Отмены / возвраты | Запрос, подтверждение и завершение различаются; повтор запроса не новый исход |
| Физический объём | Только одинаковая единица и сопоставимый товар; общая сводка разных товаров в рублях и числе заказов |

**Выход:** контрольный расчёт и все отрицательные условия сверены с первичными событиями; каждая метрика воспроизводима, без смешения коммерческих KPI и оценки агентов.

<a id="stage-13"></a>
## Этап 13. Закрыть права, документы, аудит, лицензии и эксплуатационные границы

**Статус:** реализация S13.01–S13.06 доведена по замечаниям PR #125; отрицательные сценарии, гонки допуска, отмена парсеров и восстановление проверяются регрессиями. Whisper использует предварительно подготовленный локальный кеш, загрузка весов во время пользовательского запроса отключена; реальное распознавание synthetic RU-записи проверено. Результаты полного CI привязываются к исправленному HEAD в комментарии PR. Внешние условия реального запуска (юрист, оператор, настоящая 2FA при её обещании, лицензии конкретных весов/ассетов и утверждение SBOM) остаются отдельными и явно помечены. **Владельцы:** backend, оператор, профильные специалисты, команда. **Связь:** W12–W13, W19–W20, W23; C10, C18, C27.

Этот этап завершает сверку защит, которые уже обязательны в каждом предыдущем этапе. Он не разрешает временно проводить незаконное или неподтверждённое действие ради реализации функции.

- [x] **S13.01 — вся отрицательная матрица доступа.** Расширенная матрица приватных чтений/записей/экспортов/старых ссылок по путям маркетплейса и семи типам акторов; отдельно подтверждены отказы административных действий для сотрудников без полномочий и роль/владелец агентных процессов. Смена выбранной компании не отменяет законное членство; тест потери старого доступа моделирует отзыв членства и переход в другую компанию. Отказы не меняют бизнес-данные и не раскрывают private-данные; seller-cost остаётся у продавца. Для прямого/группового/резервного/исполнительного/аналитического пути, импорта, файла и agent-task проверить анонимного, другую компанию, недостаточную роль, blocked-аккаунт, отозванное членство, администратора и смену компании. Проверять чтение, запись, экспорт и старую прямую ссылку; frontend-скрытие не защита. **Приёмка:** отказ не имеет побочного бизнес-эффекта, private-данные не попадают в ошибку/кеш/трассу, seller-cost остаётся у разрешённого продавца.
- [x] **S13.02 — жизненный цикл документов.** Общая транзакционная блокировка документов и новых обязательств; один сериализованный обработчик legacy/v3-решений. Изменения статуса, области, confirms и срока переоценивают опубликованные товары и уведомляют прямые, групповые и резервные обязательства без автоматической отмены. Фоновый проход раз в 60 секунд обнаруживает будущий/наступивший срок идемпотентно; durable outbox повторяет rematch после освобождения блокировок. Пропущенный срок сохраняется, explicit null очищает его. Баннер привязан к компании, удаление убирает документ, сбой проверки виден и повторяем. Завершить автоматическое обнаружение будущего истечения, отзыв/удаление/сужение области, повторную оценку публичного статуса, связанный rematch и уведомления затронутых сделок. Новые обязательства блокируются актуальной проверкой, действующие не удаляются автоматически: событие → ответственный → допустимое решение. **Приёмка:** истечение между просмотром и принятием останавливает новое действие; документ чужого листа/назначения не годится; повтор проверки не спамит и не уничтожает историю.
- [x] **S13.03 — аудит и диагностика.** `scrub_secrets` очищает вложенные ключи секретов, объяснения и причины согласований до хеширования; отдельно проверены access/refresh-token и маркированные строки. Непомеченный произвольный секрет нельзя гарантированно распознать regex: исходные документы/дампы запрещены как текст аудита. Удаление документа всегда сохраняет actor/метаданные в отдельном событии, даже без опубликованных товаров. Политика `docs/security/log-retention.md` честно описывает пределы redaction/retention и неизменяемости; подмена ловится `/audit/verify`. Из сделки/задачи/admin доступна только разрешённая история: actor/company, версия, инструмент, событие, outcome/reason, correlation/task ID. Проверка hash-chain показывает нарушение в тестовой копии и объясняет предел: администратор БД может переписать всю цепочку без независимого якоря. Определить redaction/retention для журналов и локальных трасс. **Приёмка:** причина решения восстанавливается без раскрытия пароля/токена/сырого клиентского документа; audit не объявлен абсолютной неизменяемостью.
- [x] **S13.04 — файлы и недоверенные инструкции.** Fail-closed MIME и настоящие декодеры PNG/JPEG/WebP/PDF/аудио; неизвестные форматы, SVG, пароли и повреждённые файлы отклоняются. Нативный парсер изолирован: wall/CPU/memory, страницы, распакованные stream, пиксели и длительность аудио ограничены; таймаут/отмена убивают и ожидают worker. Общий Gateway-путь материалов включает deadline аудио/OCR; ошибка не оставляет process в processing_sources. Реальные синтетические fixtures заменили «валидные» заголовки. Внешняя консультация принимает только четыре числовых счётчика с отдельным разрешением, включённым в идентичность запуска; пустой ключ гарантирует отсутствие отправки. Проверка реального формата/размера, пределов распаковки/парсинга, CPU/времени, OCR/аудио, доступа к объектам, безопасного вывода и очистки. Prompt injection из документа/страницы не становится инструментом/approval. Внешний консультативный маршрут выключаемый и получает только отдельно разрешённый минимальный контекст; regex не называется полной анонимизацией. **Приёмка:** вредоносный/повреждённый/слишком большой материал даёт ограниченную ошибку; внешний маршрут выключен — отправки действительно нет; права объекта проверяются при скачивании.
- [x] **S13.05 — публичная эксплуатация и право.** Матрица v0.2: дата проверки команды, доказательства по каждой норме, владелец; HTTPS/CORS/порты/секреты/лимиты/оповещение сверены и покрыты CI; имитации 2FA нет. Юрист, оператор, TOTP — отдельные условия запуска, не выдуманы. Сверить фактического оператора/контакты, пользовательские документы, основания обработки/согласий, хранение/удаление, версию принимаемых условий и реальную B2B-модель с российским специалистом по [матрице](docs/legal/compliance-matrix.md). Черновики не выдавать за действующие документы. Для сетевого доступа — HTTPS, origin/CORS, закрытые служебные порты, уникальные секреты, безопасная ротация, лимиты входа и проверяемое оповещение. До эксплуатационного запуска завершить настоящую TOTP/резервные одноразовые коды/защиту перебора/восстановление, если обещана 2FA; кнопку-имитацию не показывать. **Приёмка:** никаких вымышленных реквизитов оператора или принятой без данных оферты; новые реальные сценарии не включаются по одному снятию метки стадии.
- [x] **S13.06 — законное использование компонентов.** Node-аудит и фактический Python-состав сверены с lock-файлами (150 записей по сервисам). В перечне отдельно указаны Ollama MIT, точный ctranslate2, Pillow MIT-CMU, pypdf BSD и PyAV/включённый FFmpeg; добавленные декодеры необходимы для защиты файлов. Изображения перечислены с источниками и границами доказательств; неподтверждённые права на icon.png, лицензии конкретных весов и обязанности AGPL/LGPL/GPL остаются условиями внешнего распространения. Наличие файла в Git/SPDX и отсутствие CVE не выдаются за юридическое подтверждение. Обновить [license inventory](docs/legal/license-inventory.md): версии, лицензии, атрибуция, зависимости/модели/шрифты/изображения, происхождение lock и соответствующие исходники. Отдельно сверить MinIO AGPL, PyMuPDF, модели/OCR/Whisper и фактический способ распространения/сетевого использования; SPDX-поле и нулевой audit недостаточны. Нужное исключение/замена оформляется обоснованно. **Приёмка:** п. 6.15 подтверждается проверенным составом и обязательствами; источник MinIO/лицензия сохранены, авторские материалы и чужие ассеты не присвоены.

**Выход:** нет открытого дефекта, позволяющего обойти полномочия, раскрыть чужие материалы или принять недопустимое обязательство. Неизвестные внешние реквизиты/правовые решения остаются отдельными условиями запуска, а не придумываются в коде.

<a id="stage-14"></a>
## Этап 14. Предметные интеграции и дополнительные ИИ-инструменты

**Статус:** в [PR #126](https://github.com/NawOmen/R136a1/pull/126) приняты решения по S14.01–S14.04; live-расширения не выбраны. Файловый импорт сохраняет источник и защищает его при повторе; провайдеры отключены; внешняя консультация ограничена числовыми счётчиками и отдельным разрешением. До merge изменения не считать частью main. **Владельцы:** продукт, backend, профильный интегратор. **Связь:** W14, W26–W28; C22–C25, C27–C28.

Положение не обязывает подключить все ERP, ЭДО, реестры, платежи, MCP или A2A. Для каждой ветки сначала выбрать конкретный сценарий/провайдера и решить «реализовать» или «не применимо к текущему сценарию» с обоснованием. Нужная пользователю интеграция остаётся открытой до результата; отсутствие внешних реквизитов не блокирует внутреннее КП/учёт/исполнение.

- [ ] **S14.01 — ERP-обмен.** Выбрать российскую конфигурацию и доступ; начать read-only с каталога/цены/остатка. Mapping, authoritative source по полю, external_id, версия, время последнего успешного обмена, preview/diff, конфликт ручной правки, журнал и replay. **Приёмка при реализации:** timeout не показывает «синхронизировано»; повтор не дублирует; внешняя цена не переписывает согласованную сделку, публикация/ресурс защищены.
- [ ] **S14.02 — ЭДО, реестр и логистика.** Разделить отдельные контракты, основания доступа, лицензии и статусы источника. Файл/проверка применимости/макет накладной не равны подписанному документу; реестр не равен физической проверке производства; логистический API не делает площадку перевозчиком. **Приёмка при реализации:** provider event аутентифицирован и идемпотентен, недоступность объяснена, источник/срок видны; пока провайдер не подключён — нет ложного успеха.
- [ ] **S14.03 — поиск, RAG и внешние подсказки.** Улучшать смысловой поиск только после измеренных пропусков, сохраняя hard constraints и решение покупателя по аналогу. Retrieval фильтруется по компании до выдачи контекста; индекс связан с версией документа. Для внешних российских источников — разрешённые API/страницы/выгрузки, ссылка/время/условия/лимиты; найденная цена предварительная. **Приёмка при реализации:** нет массового обхода ограничений, отправки сообщений продавцам без поручения, загрузки private-файлов или превращения подсказки в допуск.
- [ ] **S14.04 — MCP/A2A, оркестрация и трассы.** Сначала устойчивый внутренний контракт этапа 04, затем минимальный адаптер выбранного внешнего сценария с версией, allowlist, scope, бюджетом и совместимостью. Долгие задачи можно решить состоянием БД и worker; очередь/новый сервис оправдывать измеренным узким местом. Подбор средств — [реестр источников и ИИ-инструментов](docs/research/contest-sources-and-ai-tooling.md), навыков — [инструменты проекта](docs/frontend/design-tooling.md). **Приёмка при реализации:** внутренний продукт работает без адаптера, сбой не удваивает write, private-данные не расширяют контекст внешнего агента; новый framework имеет необходимость, совместимость и лицензию.

**Фактические решения S14 (PR #126, исходная реализация `3f3d779`).** Пункты выше сохраняют критерии будущих выбранных расширений; отсутствие подключения не выдаётся за выполненную live-интеграцию.

| S14.01 | Live ERP не применимо к текущему сценарию: нет выбранной российской конфигурации, доступа и договорённости. Поддерживается файловый импорт с preview, подтверждением, внешними ID и аудитом. `source_system` сохраняется в импорте; повтор того же ключа и файла возвращает исходную метку, конфликт метки даёт `409`. | Mapping/authoritative source по полю и живая синхронизация не реализованы.
