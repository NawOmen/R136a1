# Реализация согласованного плана

Рабочая ветка: `codex/product-completion`. Этот журнал отражает фактическое состояние работы, а не обещание завершённости. Исходные требования: [план проблем бизнеса](research/business-problems-action-plan.md), [продуктовое направление](product-direction.md), [сценарии и аналитика](product-experience-and-analytics.md).

## Выполненные изменения, требующие общей сквозной приёмки

- Статистика ИИ сохраняет компанию в момент запуска, разделяет локальный, внешний, смешанный маршрут и правила. Старые запуски без компании не приписываются компании по текущему членству пользователя.
- События приёмки, возврата и отмены учитываются отдельно. Приёмка — действие покупателя после отгрузки, возврат/отмена — запрос с решением другой стороны. Повторы имеют ключ идемпотентности, количество проверяется повторно при решении.
- Цена единицы и доставка фиксируются в сделке. Историческим сделкам без снимка цена не выдумывается.
- Себестоимость и прочие расходы сохраняет продавец с контролем версии. Покупатель не получает эти поля и примечания. Неизвестные расходы и платежи не заменяются нулём.
- Отчёты продавца и покупателя фильтруются по периоду создания заказа (UTC) и категории. Исполнение в них — текущее состояние выбранных заказов. Выгрузка CSV строится из той же разрешённой выборки.
- В форме потребности текст/поля сохраняются в текущей вкладке отдельно для пользователя и компании. Файлы не сохраняются в браузерное хранилище; для продолжения незавершённой загрузки требуется повторный выбор. Повтор запроса создания возвращает прежний черновик, повтор идентичного вложения не создаёт дубль.
- Выбор КП требует явного согласия на его ревизию; изменение КП требует ожидаемую ревизию. Старые клиенты без предусловия получают 428 на выбор; это намеренное ограничение безопасности API v1. Актуальный клиент передаёт необходимые поля.
- Начат общий реестр склада, мощности и удержаний. Он учитывает параллельные обязательства, срок удержания, потребление при отгрузке и освобождение неиспользованного ресурса. Нельзя уменьшить склад/мощность ниже действующих обязательств.
- Исправлено стирание остатка при редактировании названия товара. Источник складского КП — конкретный товар, остатки разных товаров не суммируются.
- Удалены обозначения стадии разработки из основных экранов. Убраны неподключённые тарифы и ложная формула загрузки мощности.
- Python приведён к 3.12 в инструкциях, Dockerfile и CI; локальные окружения созданы с этой версией.

## Ограничения выпуска

Информационные страницы «Правила работы» и «Конфиденциальность» описывают функции, но не заменяют юридически подготовленные соглашение и политику оператора. Реальные реквизиты оператора, основание обработки персональных данных и контакт для юридических обращений в проекте не заданы. До публичного коммерческого запуска требуется заполнить их и провести проверку. Названия синтетических компаний и локальные аккаунты не являются подтверждёнными клиентами или продажами.

## Проверка интерфейса

| Before | After | Why |
| --- | --- | --- |
| Созданные сделки показаны как продажи | Заказ/приёмка/возврат/отмена имеют разные показатели | Итог соответствует зарегистрированному исполнению |
| Неизвестные затраты не отражались | «Нет данных», полнота покрытия, отдельная форма затрат | Пользователь видит основание прибыли |
| После ошибки загрузки создавался новый черновик | Повтор продолжает сохранённый запрос | Нет дублирующих потребностей |
| Цена могла измениться между просмотром и выбором | Явное подтверждение ревизии | Согласие относится к показанным условиям |

## Последнее уточнение объёма проверок

По поручению пользователя концепция дизайна сохраняется. Дальше выполняются короткие проверки изменённых функций, без полного тестирования сайта. Ранее выполненные проверки остаются полезными результатами, но не являются условием повторения всей проверки после каждой правки.

Проверено точечно: редактирование/конфликт ревизии/запрет изменения опубликованной заявки; скрытие товара при истечении и отзыве документов; подбор по характеристикам; неизвестная надёжность; групповые предложения. Проверка TypeScript проходит. Два последовательных наполнения изолированного стенда дали неизменные 3 компании и 23 товара (21 новый + 2 старых); 9 помечены опубликованными, остальные требуют документов. Это синтетические записи, не продажи. Текущий набор описан в [происхождении ассортимента](synthetic-assortment.md).
