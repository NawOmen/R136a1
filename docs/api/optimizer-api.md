# Optimizer API v2: точные деньги

Базовый локальный адрес: `http://localhost:8004`.

Marketplace вызывает `/api/v2/optimize/...`: цены и суммы — десятичные строки.
Приведённые ниже v1 маршруты продолжают работать с числовыми ответами для старых
потребителей. Доступ к обеим версиям требует действующего сервисного ключа.

Цены единицы допускают 12 дробных знаков; бюджеты, доставка и дополнительные
расходы вводятся до копейки. Итоговая сумма строки — ROUND_HALF_UP после умножения
целого количества на полную цену единицы. CP-SAT вычисляет целые копейки через
целочисленное деление: `(коэффициент × объём + масштаб/2) // масштаб`;
масштаб десятичной цены не выше 10^12. Числитель отдельной строки и суммарные домены
всех ценовых ступеней/целевых функций ограничены 2^61. Превышение даёт понятный 422,
а не усечение цены или сообщение «решения нет» при переполнении. Общая стоимость
также ограничена денежным диапазоном платформы `999999999999.99` ₽.

`additional_cost_rub` добавляется один раз при выборе производителя, отдельно от
товара и доставки. В группе товар считается сначала для общей партии, затем
копейки распределяются пропорционально объёму по наибольшим остаткам со стабильным
порядком ID. Сумма участников совпадает со стоимостью партии. Дополнительные
платные статьи группы приходят из полной сметы marketplace, где их источники
и распределение сохраняются отдельно.

Хэш включает точные денежные строки, версию денежного контракта и
`comparison_context` с версиями КП/потребности и условиями сравнения.
`reserve_holding_total_rub` включается в базовую и новую конфигурацию как уже
понесённый согласованный расход; цена замены содержит условное переключение,
но не повторную плату за прежнее удержание. Неизвестное полное покрытие не даёт
ложного процента экономии.


## `POST /api/v1/optimize/allocations`

Принимает требуемый объём, бюджет, срок и список российских производителей с
MOQ, мощностью, ценой, ценовыми ступенями, логистикой и коэффициентом надёжности.
Возвращает от одного до трёх различных вариантов: `cheapest`, `balanced`, `reliable`, распределение по
производителям, итоговую стоимость, срок, объяснение и `input_hash`. Одинаковые выполнимые распределения и одинаковые причины отсутствия решения не дублируются. Неизвестный рейтинг остаётся NULL; при недостаточных данных рейтинговое преимущество не применяется.

## `POST /api/v1/optimize/coalition`

Проверяет общую производственную основу, жёсткие ограничения, MOQ, мощность,
ценовую ступень, индивидуальные операции, логистику, бюджет, срок и выгоду
каждого покупателя. Отрицательная индивидуальная выгода сохраняется в ответе и сама по себе не подменяет проверку выполнимости; решение принимает покупатель.

## `POST /api/v1/score/opportunity`

Считает `opportunity_score` по зафиксированным весам подтверждённого спроса,
дефицита предложения, Capability Passport, MOQ/мощности, логистики, конкуренции
и качества данных. Расчёт не является прогнозом прибыли.

## `POST /api/v1/optimize/resilience`

Принимает основное распределение, резервные варианты и разрешённые покупателем
пороги цены/срока. Детерминированно строит все N-1 и N-2 сценарии, сохраняя
незатронутые назначения, и возвращает подтверждённое покрытие, вероятное
покрытие, дефицит, изменение цены и срока. Резерв считается подтверждённым
только при действующем согласии производителя и дате удержания мощности.

Если часть выпавшего объёма не покрыта, `cost_comparison_applicable=false`, а
`new_total_cost_rub`, `price_delta_rub` и `price_delta_pct` возвращаются как
`null`: частичную стоимость нельзя сравнивать с полной базовой конфигурацией.

## S09: статусы решателя и лимит времени

Каждый сценарий N-1/N-2 содержит `solver_status`: `optimal`/`feasible` —
решение найдено; `infeasible` — допустимого распределения нет ни при каких
затратах времени; `timeout` — лимит исчерпан раньше решения (не выдаётся
за отсутствие решения). Лимит задаётся `time_limit_seconds` (по умолчанию 10,
максимум 60). Одна компания считается одним независимым риском: повтор
основного производителя в запросе отклоняется 422.
