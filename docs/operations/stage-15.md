# Эксплуатация и проверка этапа 15

Статусы задач и приёмочных условий ведутся только в `NEXT_STEPS.md`. Этот документ — инструкция оператора, а не параллельная очередь. Все примеры и измерения используют синтетические компании и документы.

## Версии и безопасный запуск

1. Зафиксируйте commit (`git rev-parse HEAD`), Docker image ID (`docker compose images`), миграции трёх схем, реестр категорий и контрольные суммы данных. Снимок сохраняет commit checkout, image ID, OCI revision образа (если задана), commit исходников, подключённых из этого checkout в `/app`, и заявленные модели из `infra/models.lock.json`; Незакоммиченные исходники блокируют снимок. `null` в image revision означает неизвестную версию приложения в образе, а не совпадение с checkout; без bind-mount восстановите приложение из зафиксированного commit или размеченного образа. Фактические digest модели проверяются отдельно через локальный Ollama `/api/tags`.
2. Создайте `.env` через `scripts/init-local-env.py`. Файл, TLS-ключи и резервные копии храните вне Git с доступом только оператора. Снимок не включает секреты, ключ подписи JWT и кеш моделей: восстановите их из отдельного защищённого хранилища. Смена ключа JWT требует нового входа.
3. Подготовьте локальные артефакты до отключения сети: образы по lock-файлам, Ollama `qwen3.5:9b`, faster-whisper `small`/`int8`, OCR и сертификат HTTPS. Наличие имени в lock-файле не доказывает наличие кеша. Не скачивайте модель при обработке запроса.
4. Порядок запуска задаётся Compose healthchecks: PostgreSQL → auth; MinIO/optimizer/auth → marketplace → LLM Gateway → web → HTTPS edge. Entrypoint применяет миграции перед запуском. Seed разрешён только на выделенной синтетической базе; для восстановления `ENABLE_DEMO_SEED=false`.
5. После запуска проверьте health, вход обеих ролей, каталог и незавершённую задачу. Недоступность обязательной модели означает ограниченную ошибку и ручной путь; внешний review необязателен. Не трактуйте `ready_for_review` как исполненное обязательство.

## Согласованный снимок

В окно обслуживания закройте доступ к сайту и остановите **всех** писателей БД/объектов, включая внешние worker, ручные импорты и служебные инструменты. Остановите `gateway-auth`, `marketplace`, `llm-gateway`, `minio`; PostgreSQL оставьте работающим. Скрипт проверяет известные контейнеры Compose, но не может обнаружить внешнего клиента БД.

```bash
python3 scripts/operations.py backup --project YOUR_PROJECT --directory /absolute/private/snapshot
```

`pg_dump -Fc` сохраняет все три схемы, ревизии, approval, аудит, ledger и задачи. Архив MinIO снимается со **остановленного** тома, поэтому запись файла не может разойтись с записью его ссылки. Manifest создаётся только после обеих успешных операций; SHA-256 проверяет целостность, не подлинность. Каталог содержит приватные данные, права `0700`, файлы `0600`. Используйте шифрованный носитель и отдельную защищённую копию. Не публикуйте дамп или manifest клиентской системы в PR.

После снимка запустите прежние сервисы. Ошибка backup не меняет данные и не запускает остановленные сервисы автоматически.

## Восстановление на отдельной копии

Вне Git задайте `RESTORE_POSTGRES_PASSWORD`. Используйте новое имя проекта, отличное от источника:

```bash
python3 scripts/operations.py restore --project YOUR_NEW_PROJECT --directory /absolute/private/snapshot
```

Скрипт запрещает существующие контейнеры и тома назначения; имя временного `restore-lock` резервируется атомарно до записи, чтобы два одновременных восстановления не делили тома. Он проверяет обе суммы и пути архива до записи, использует локальный неизменяемый ID PostgreSQL-образа, создаёт два новых тома. База разворачивается без опубликованного порта; restore транзакционный и останавливается при первой ошибке. Не удаляйте исходный проект. При неудаче новые тома и `restore-lock` сохраняются для диагностики; повтор требует нового имени либо осознанной уборки именно этих томов.

Перед подключением приложения:

- Сравните версии миграций, строки историй ревизий/approval/resource ledger, контрольную сумму незавершённой задачи и бинарные файлы с исходной копией.
- Запустите MinIO той же версии на восстановленном томе; проверьте download по каждой сохранённой ссылке и её SHA-256, а не только число файлов. Используйте `scripts/verify-restored-history.py` до запуска писателей и `scripts/verify-restored-objects.py` внутри marketplace-образа с `MINIO_COPY_ENDPOINT` отдельной копии.
- После сверки остановите и удалите временный контейнер `<NEW_PROJECT>-restore-postgres`, **сохранив том**. Если MinIO запускался для проверки отдельно, остановите и его. Только затем подключайте тома к целевому Compose с тем же именем нового проекта: нельзя запускать два PostgreSQL или два MinIO на одном томе. Запустите тот же commit приложения с соответствующими секретами, выключенным seed и восстановленными томами. Не применяйте downgrade к исходной базе.
- Перезапустите LLM Gateway: незавершённая задача сохраняет ID/ревизию/approval. Возобновление выполняется через versioned resume после истечения heartbeat, с лимитом попыток; повтор согласия не должен создавать второе обязательство.

## Локальная сеть и оборудование

Для второго устройства используйте `infra/docker-compose.https.yml`, доверенный сертификат с SAN фактического адреса и явный `CORS_ORIGINS=https://ADDRESS`. Не публикуйте напрямую БД, MinIO или optimizer. `scripts/print-access-url.py` показывает кандидат адреса, но не проверяет доступность или доверие.

На MacBook проверьте свободный диск, питание от сети, отключение сна на время показа и доступный кеш. Микрофон требует secure context и разрешения браузера; при отказе загрузка аудиофайла сохраняет рабочий путь. Автоматические проверки отказа микрофона не доказывают работу физического микрофона. Доверие на втором устройстве и физический ввод фиксируются только после реального прогона.

## Измеряемый объём и пределы

Первичная цель для локального синтетического сценария: два параллельных клиента, 20 вычислений распределения, 25 поставщиков, 100 единиц; p95 ≤ 5 с, HTTP timeout 15 с. Это проверяемая инженерная цель данного прогона, не промышленный SLO.

```bash
python3 scripts/measure-runtime.py --samples 20 --concurrency 2 --slo-seconds 5
```

`OPTIMIZER_TOKEN` и `OPTIMIZER_URL` задаются вне Git. Probe проверяет 100 распределённых единиц и 1 000 ₽, отказ `422` для 26 поставщиков, пишет latency/status без токенов. Размеры ограничены сервером: ≤25 поставщиков/тарифов, ≤100 участников коалиции; timeout solver и лимиты процесса смотрите в текущих schemas/solver/Compose. Файлы ≤25 MiB каждый, суммарный текст ≤120 000 символов; локальная LLM 180 с, OCR/material processing 240 с, Whisper 180 с, nginx 240 с. Лимиты не означают успешную обработку любого материала максимального размера.

Во время сопоставимого прогона снимайте `docker stats --no-stream` и `pg_stat_activity`/`pg_locks` отдельно. HTTP-время включает ожидание потока; отдельной durable очереди solver нет. Отсутствие блокировок в одной выборке не доказывает отсутствие contention. Проверки resource races и повторного approval выполняются тестами бизнес-инвариантов. Новая очередь или декомпозиция оправданы только измеренным узким местом.

Карта выбранных инвариантов: `docs/operations/acceptance-tests.json`. Отчёт строится `python3 scripts/acceptance-report.py /private/marketplace.xml /private/llm-gateway.xml /private/optimizer.xml`; имена JUnit-файлов должны содержать имя сервиса, как в примере. Отсутствие evidence остаётся `unverified`; T35 требует все девять параметров.
