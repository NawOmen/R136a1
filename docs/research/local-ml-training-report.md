# Локальная адаптация ИИ ПоРукам: результаты экспериментов

Снимок состояния: **2026-10-13 19:34 +07**. Это технический отчёт об экспериментах, а не новый план разработки и не заявление о полной готовности модели.

## Вывод

Buyer-адаптер v4 улучшил разбор синтетических запросов, однако свободные формулировки и перенос результатов в продуктовые контракты требуют дополнительной проверки. Buyer v6 сейчас обучается. Для помощника платформы улучшение промпта и схемы ответа дало 32/32 правильных ответов на небольшом закрытом наборе без дообучения весов. Объяснения продавца проходят формат после изменения промпта, но пока содержат фактические ошибки.

Обученные адаптеры и экспериментальные промпты **не подключены к приложению**. Данные синтетические, независимой предметной экспертизы нет. Результаты не являются коммерческими показателями.

## Устройство и воспроизводимость

MacBook Pro 2021, Apple M1 Pro, 16 ГиБ общей памяти. Для Buyer используется локальная `mlx-community/Qwen3.5-9B-8bit`, ревизия `16daa4818c54ce5f5436f929d52542eb65bbed9d`, с LoRA последнего слоя: rank 32, scale 2, dropout 0,05. Модель лицензирована по Apache-2.0, MLX-LM — MIT; копии лицензий сохранены в лаборатории.

Лимит MLX — 11,8 ГиБ; пиковые значения ниже приведены в десятичных ГБ. Проверка v3 с двумя обучаемыми слоями превысила лимит; один слой прошёл пробу. Для v6 проба самых длинных примеров прошла с пиком 12,079 ГБ. Это подтверждение конкретной конфигурации, не доказательство стабильной работы всего приложения одновременно с моделью.

Используется loss только по токенам ответа с проекцией по частям. Его значения и градиенты сверены со стандартным MLX на 24 CPU-кейсах. Исходники запусков, настройки, версии окружения, контрольные суммы данных и весов, loss, память, журналы и ответы сохранены локально. Один тяжёлый GPU-процесс допускается за раз; MLX и эксперименты Ollama выполняются последовательно.

## Buyer extraction

Все перечисленные Buyer-корпусы пока покрывают четыре категории: бумажные стаканы, крепёж, упаковку и металлообработку. Оцениваются категория, JSON, полностью правильный ответ, факты, единицы, точные цитаты, пропуски и лишние факты. Падение loss не считается доказательством качества.

| Эксперимент | Проверка | Полностью верные ответы | F1 фактов | Лишние факты | Ограничение |
| --- | --- | --- | --- | --- | --- |
| v3, выбран шаг 768 из 1024 | 96 test + 16 отдельно написанных запросов | 101/112 | 0,9847 | 5 | Отдельно написанные: 9/16 |
| v3-адаптер на новом наборе v4 | 160 test + 8 отдельно написанных запросов | 112/168 | 0,9340 | 43 | Это сравнение на другом наборе, не ухудшение результата v3 на его прежнем test |
| v4, продолжение на 512 минибатчах | Тот же закрытый набор v4 | 151/168 | 0,9892 | 2 | Отдельно написанные: 4/8 |
| v5, лучший кандидат для разбора ошибок | 64 valid | 29/64 | 0,9094 | 22 | Допуск не пройден; 28 valid теряют специфику материала в эталоне |

Выбор v3/v4 зафиксирован по valid до финальной генерации. V4 прошёл 62/64 полностью правильных ответов на valid без лишних фактов. Его финальный test нельзя использовать для дальнейшего выбора весов: после разбора ошибок это регрессия.

В v5 фраза «углеродистая сталь» размечалась общим значением «сталь» без явного правила нормализации. Более специфичный ответ штрафовался. Кроме дефекта gold, у выбранного кандидата отмечены 13 ошибок цитат и один невалидный JSON. V5 test и natural-test не использовались для итоговой оценки; корпус сохранён для аудита.

### Текущий v6

2432 train, 128 valid, selection 64 из valid, 160 закрытых test и 16 новых отдельно написанных синтетических natural-test. В промпте явно заданы строковые материалы, нормализация словоформ и сохранение специфики углеродистой стали. Примеры не обрезаются: максимум train 1091 токен, конфигурация контекста 1280. При подготовке генератор отклонил 701 длинного кандидата; это смещает корпус к коротким сообщениям и ограничивает выводы о длинных документах.

Старт с сохранённого v4, LR 2e-5, накопление градиента 2. Запланировано 1024 минибатча, то есть 512 обновлений оптимизатора; это частичный этап, а не полный проход всех 2432 строк. На момент снимка: **630/1024**, `finished=false`, пик **12.043 ГБ**. Итоговая генерационная проверка v6 ещё не выполнена. После обучения последовательный процесс сравнит четыре сохранения с исходным v4 по valid.

## Другие ИИ-задачи

**Platform Assistant.** Установленная Ollama `qwen3.5:9b` Q4_K_M проверена с JSON Schema, `think=false`, temperature 0,1 и контекстом 8192. Кандидат v2 ограничивает `source_ids` четырьмя существующими источниками через enum и уточняет промпт. Версия зафиксирована на valid 20/20 до закрытого test: **32/32**, JSON 100%, p95 **2.122 секунды**. Это адаптация обвязки без новых обученных весов и прямой локальный Ollama-вызов, не полный HTTP Gateway-тест. Смешанные вопросы, права и обновление справки ещё не проверены.

**Seller Explanation.** Исходная обвязка дала 9/16 допустимых по формату/длине ответов: один тайм-аут и шесть ответов длиннее 1500 символов. Краткий промпт улучшил формат до 16/16, но агентское ревью обнаружило ложные совпадения материала, утверждение об отсутствующем минимальном заказе при заполненном поле и вывод о месте производства из региона доставки. Семантический допуск не пройден, закрытый test этого банка не использован.

Подготовлен отдельный seller-v2: 512 train, 64 valid и 64 закрытых test. Эталоны содержат `gold_claims` с основаниями из паспорта; CPU-проверки формата, утверждений, диапазонов, уникальности и длины пройдены. Черновик seller-v1 отклонён до обучения из-за противоречия материалов. Обучение seller-v2 ещё не запускалось. Оценщик удаляет эталонный ответ из prompt, отделяет exact match от семантической оценки и требует проверки выводов; совпадение текста или валидный JSON не означают готовность.

**OCR, vision и Whisper.** Этот отчёт не содержит новых результатов их обучения или итоговой проверки. Текстовый Buyer-корпус не подтверждает качество распознавания документов, изображений или речи.

Свободная MLX-генерация без schema grammar ранее дала нулевой JSON-rate для двух новых ролей. Она не эквивалентна structured-output обвязке Gateway и не является доказательством дефекта модели в приложении; исходные отчёты сохранены с этим ограничением.

## Совместимость с приложением

Исследование контрактов выполнено на рабочей базе `e5483b7`; данный PR документации основан на `4b7730b`. Выводы о переносе полей требуют повторной сверки перед интеграцией на актуальной версии приложения.

Снимок реестра содержит 47 листьев, из них 46 поддерживаемых; медицинские расходники исключены из поддерживаемого охвата. На чистых marketplace-валидаторах выполнены CPU-пробы для 46 профилей: форма, обязательные поля, единицы и отклонение некорректных числовых значений. Это структурные проверки, не модельный benchmark и не предметная сертификация.

Для переноса в потребность важны точные русские leaf label и поля `technical_profile`. `category_id` не предусмотрен в текущем `RawExtraction`. Старый ключ `material_grade` не заменяет автоматически `material` или `grade`; отдельный `length_mm` не заполняет `dimensions_mm`, где оно требуется. `packaging` не является материалом коробки во всех профилях. `original_unit` служит доказательством исходной единицы и самостоятельно не создаёт характеристику `unit`.

Следовательно, качество извлечения старого корпуса не доказывает корректное создание Need во всех категориях. Проверка через Gateway и продуктовые контракты остаётся обязательной до применения адаптера. Цена, распределение объёма, резервы, Marketplace/Coalition/Resilience и сделки остаются за обычным кодом, OR-Tools и Human Approval.
