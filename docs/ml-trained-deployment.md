# Локальная обученная модель

## Имя и состав модели

Публичная версия для новых задач Gateway: `porukam-buyer-qwen3.5`. Это runtime-идентификатор: он сохраняется в поле `model_version` и связывает трассу задачи с настройками модели.

Веса не менялись при переименовании. Это база `mlx-community/Qwen3.5-9B-4bit`, revision `8b2b98c00a6b4d291155e4890773ca8f769aee53`, плюс LoRA-адаптер SHA256 `b2cf30b111109ee10439b4308cb97058ab00a85115eedd36118bbc534e52b665`. Опубликованный комплект сохраняет прежний артефактный идентификатор `porukam-buyer-b2cf30b11110`, чтобы его метаданные и контрольные суммы Release остались проверяемыми. Связь между runtime-именем и комплектом зафиксирована в `infra/models.lock.json`.

MLX API внутри использует `default_model`: это имя модели, которую сервер загрузил через `--model` и `--adapter-path`. Внешний маршрут Gateway остаётся `local_qwen` ради совместимости API. Это разные технические идентификаторы.

## Локальный запуск

Сайт и сервисы работают в Docker Compose. MLX запускается нативно на хосте с Apple Silicon; порт не публикуется в интернете. Gateway обращается к нему через приватный адрес хоста:

```dotenv
LOCAL_LLM_BACKEND=mlx
MLX_BASE_URL=http://host.docker.internal:8080
TRAINED_MODEL_VERSION=porukam-buyer-qwen3.5
MLX_MAX_TOKENS=640
OLLAMA_VISION_MODEL=qwen3.5:9b
```

Базовые веса нужны вместе с адаптером; они не преобразуются в Ollama или GGUF. Проверка файлов без запуска модели:

```sh
/path/to/mlx-python infra/build_local_model.py --base /path/to/model-9b-4bit --adapter /path/to/porukam-trained-current
```

Запуск сервера — только отдельной командой оператора:

```sh
/path/to/mlx-python infra/build_local_model.py --base /path/to/model-9b-4bit --adapter /path/to/porukam-trained-current --host 127.0.0.1 --port 8080 --serve
```

Скрипт проверяет SHA адаптера, конфигурации и файлов базовой модели, затем использует MLX-LM 0.32.0. Он не скачивает модель и не устанавливает зависимости. MLX-server должен быть доступен Gateway с хоста, но не должен быть открыт в публичный интернет. При сбое MLX Gateway возвращает ошибку; автоматического переключения текстовых запросов на базовую Qwen нет. Vision и распознавание речи остаются отдельными локальными компонентами.

## Скорость: размышления отключены всегда

Обученная модель отвечает без режима размышлений: Gateway отправляет
`chat_template_kwargs={"enable_thinking": false}` и добавляет мягкий переключатель
`/no_think` в системное сообщение. Настройки для включения reasoning нет.

Замер на живом стенде (`qwen3.5:9b`, тот же промпт и схема): с размышлениями 366 с и
6 670 выходных токенов, без них — 35 с и 563 токена, при одинаковой скорости генерации
(≈19 т/с). На этом же тексте reasoning-режим склеил диаметр и длину в одно поле
`dimensions_mm`, поэтому отключение ещё и сохраняет точность разбора.

Старый MLX-сервер, не знающий `chat_template_kwargs`, получает повтор без этого поля —
`/no_think` при этом остаётся. Если модель всё же вернула блок `<think>…</think>`,
он снимается до разбора JSON; строки внутри JSON не затрагиваются.

Контекст оставлен прежним: `LLM_CONTEXT_TOKENS=8192` для Ollama (`num_ctx`), у MLX-сервера
контекст задаётся при загрузке модели. Замеры показали, что вход у нас маленький
(≈690 токенов), поэтому окно не является рычагом скорости — время определяется объёмом
ответа. Уменьшать `MLX_MAX_TOKENS` до 320 нельзя: демо-заявка требует 563 токена.

## Переключение режимов и отсутствие адаптера

Режим выбирается переменной `LOCAL_LLM_BACKEND` и применяется при пересоздании
Gateway (`up -d --force-recreate llm-gateway`; обычный `restart` новый `.env` не читает):

| Режим | Настройки | Что разбирает текст | Что распознаёт изображения |
| --- | --- | --- | --- |
| Обученная модель, по умолчанию | `LOCAL_LLM_BACKEND=mlx`, `MLX_BASE_URL` | адаптер `porukam-buyer-qwen3.5` в MLX | `OLLAMA_VISION_MODEL` через Ollama |
| Технический обход без Apple Silicon | `LOCAL_LLM_BACKEND=ollama` | `qwen3.5:9b` через Ollama | `OLLAMA_VISION_MODEL` через Ollama |

Режим `ollama` нужен только для стендов без Apple Silicon и для отладки; рабочим режимом
показа он не является.

Каталог адаптера `ml/training/porukam-trained-current` содержит конфигурацию, манифест и
служебный сервер, но не веса: файл `adapters.safetensors` оператор получает из опубликованного
комплекта и сверяет SHA256 через `infra/build_local_model.py`. Без проверенного адаптера
Gateway отвечает 503 с сообщением о недоступной обученной модели; тихой подмены на базовую
Qwen нет. Состояние выбранного backend и фактическое имя модели видны в `GET /health`
(`local_backend`, `local_model`, `vision_model`), а `scripts/check-final-demo.py` проверяет
именно тот движок, который выбран: MLX `/v1/models` или Ollama `/api/tags`.

## Проверки качества и ограничения

Завершённая внутренняя валидация обученного адаптера: 404 из 412 точных ответов, micro-F1 по фактам — 99,55%, валидный JSON и категория — 100%. Данные синтетические; значение не является семантической точностью. Полная ручная проверка и независимая экспертная оценка не выполнены, автономное применение не принято.

В парном тесте на 11 синтетических заявках модель дала 11/11 полностью точных извлечений против 5/11 у базовой Qwen3.5:9B; F1 по фактам — 100% против 85,45%. JSON и категория были корректны в 11/11 случаев у обеих моделей. Медианное прямое время инференса составило 14,9 с у адаптера и 8,8 с у базовой модели.

В пяти сквозных сценариях Gateway обе модели успешно завершили по 2 из 5. Медианное полное время Gateway составило 22,7 с для обученной модели и 9,7 с для базовой. Это малые синтетические выборки: они показывают улучшение точного извлечения фактов в проверенном наборе, но не улучшение общей успешности агента; обученная модель отвечала медленнее.

Адаптер обучен на извлечении фактов. Качество объяснений и других генеративных задач отдельно не подтверждено. Цена, объём, резерв и статус сделки проверяются обычным кодом; критичные действия остаются под Human Approval Guard. Метрики обучения и локальные результаты развернутой проверки описывают разные наборы и не смешиваются.

Метаданные и README внутри каталога `ml/training/porukam-trained-current` являются снимком опубликованного комплекта и сохраняют его исходные контрольные суммы. Актуальный runtime alias и состояние локальной проверки ведутся в этой инструкции и `infra/models.lock.json`.
