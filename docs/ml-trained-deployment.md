## Подготовка оператором (Apple Silicon)

Нативный Python с проверенным MLX-LM **0.32.0**, MLX и зависимостями из приложенного lock-файла. MLX требует macOS/Apple Silicon; этот путь не является CUDA/Linux/контейнерной конвертацией. Gateway использует существующий HTTPX, новых production-зависимостей у него нет. База/адаптер не импортируются в Ollama и не сливаются в GGUF.

Проверка без загрузки модели и без запуска сервера:

```sh
/path/to/mlx-python infra/build_local_model.py --base /path/to/model-9b-4bit --adapter /path/to/porukam-trained-current
```

Только когда оператор решит разворачивать:

```sh
/path/to/mlx-python infra/build_local_model.py --base /path/to/model-9b-4bit --adapter /path/to/porukam-trained-current --host 127.0.0.1 --port 8080 --serve
```

Сервер получает `--adapter-path`, выключенный thinking и лимит MLX9GiB. GPU-обучение не запускается. HTTP API MLX использует `model=default_model`: это привязка к проверенной базе и адаптеру, а не имя для скачивания. Не предоставлять MLX server напрямую пользователям: он допускает загрузку моделей по API. На машине Gateway или через защищённый SSH-туннель/приватный интерфейс настроить доступ; публичный bind запрещён политикой развёртывания. При контейнерном Gateway `127.0.0.1` внутри контейнера не является хостом: использовать приватный host endpoint `host.docker.internal` и проверить доступность с контейнера. Порт8080 в Compose не публикуется.

Параметры Gateway:

```dotenv
LOCAL_LLM_BACKEND=mlx
MLX_BASE_URL=http://host.docker.internal:8080
TRAINED_MODEL_VERSION=porukam-buyer-b2cf30b11110
MLX_MAX_TOKENS=640
OLLAMA_VISION_MODEL=qwen3.5:9b
```

Vision и распознавание речи не обучались этим LoRA-адаптером; они остаются отдельными локальными компонентами. Оригинальная Qwen для **текста** автоматически не используется. Для ручного отката оператор может явно задать `LOCAL_LLM_BACKEND=ollama` и `OLLAMA_MODEL=qwen3.5:9b`; это другой маршрут, не наш адаптер.

## Приёмка и ограничения

До реального переключения оператор проверяет `/v1/models`, синтетический `/v1/chat/completions`, затем запрос через Gateway и фактическую версию в трассе. Gateway проверяет JSON и Pydantic-контракт; MLX не получает Ollama `format` и не обещает grammar-constrained decoding. Невалидный/обрезанный JSON даёт ошибку. Обучающий контекст1280, completion512; более длинные продуктовые запросы и задачи за пределами извлечения требуют отдельной оценки. Максимум640 в проверке не означает доказанное качество на длинном контексте. Производительность serving не измерялась; пик5.939GB — метрика обучения. Не запускать модель одновременно с обучением или другим тяжёлым GPU-процессом.

Текущий PR содержит проверенный код переключения и артефакты; **live smoke Gateway и эксплуатационная приёмка не выполнялись по указанию пользователя не выполнять развёртывание**. Нельзя считать отсутствие этих результатов пройденной проверкой.
