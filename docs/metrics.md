# Коммерческие метрики

### Словарь `commercial-analytics-2`

| Показатель | Определение |
|---|---|
| Заказано | Согласованное количество `Deal.units`, отдельно от исполненного |
| Куплено / продано | Подтверждённая приёмка минус подтверждённые возвраты (`net_units`); отгрузка не является приёмкой |
| Цена сделки | Замороженная цена/смета, текущий каталог не меняет прошлое |
| Средняя цена | Net-выручка / net-количество внутри одной замороженной спецификации, единицы и условий; при полном возврате или неизвестной спецификации значения нет |
| Сумма заказов | Согласованная сумма когорты, включая доставку и статьи сметы; это не платёж |
| Выручка товаров | `unit_price_rub × net_units`, округление строки HALF_UP до копейки |
| Себестоимость | `unit_cost_rub × net_units`, источник, версия и начало действия подтверждены продавцом |
| Валовая прибыль | Сопоставимая выручка − себестоимость. При одинаковой известной базе — прямо; цена с НДС при известной ставке приводится к затратам без НДС. Неизвестная/несопоставимая база → null с причиной |
| После прямых расходов | Валовая прибыль − указанные расходы заказа целиком; неполные расходы не являются чистой прибылью |
| Деньги и чистая прибыль | Не рассчитываются без подтверждённых платежей и полного состава расходов/налогов |
| Отказы | Когорта предложений по созданию: rejected / (rejected + selected); открытые и истекшие отдельно. `sent` с прошедшим `valid_until` является истекшим, не открытым |
| Физический объём | Не суммируется по разным спецификациям даже при одной единице |
| Месячная сумма | Полная сумма только при известной цене каждого заказа; рядом число заказов с известной ценой. Частичная известная сумма не называется полной |
| Надёжность | `execution-reliability-1`: фактические исходы заказов и замороженный срок. Вовремя без отмен/возвратов / известные исходы; просроченный открытый заказ — отрицательный исход. Минимум 5, иначе «Не оценено» |

### Периоды, история и экспорт

Даты — UTC, границы включительно. Заказы и месячные итоги — когорта по созданию
заказа с исполнением на `built_at`; `period_events` — события по подтверждению
(`decided_at`, иначе `created_at`), в том числе по старым заказам. Когорта отказов КП
задаётся отдельно. Фильтры применяются и к прямым, и к групповым обязательствам.

Цена, товар и спецификация берутся из замороженных условий. Возвраты относятся
к приёмкам по FIFO; это учётное распределение, не доказательство физической партии.
История затрат сохраняет версии и начало действия; неизвестная история не восстанавливается
выдуманными данными. Поздние операции дают отметку `historical_recalculated`.
Групповые суммы показываются отдельно и не удваивают выручку.

Отчёт сохраняет ID, время, фильтры и снимок с хешем; CSV по этому ID использует тот же
снимок и текущие права. Несовпадение фильтров — 409, запрос без ID строит новый отчёт.
Защита от формул применяется ко всем ячейкам. Себестоимость, примечания и прибыль
доступны только продавцу с `can_sell`, не покупателю и не чужой компании.

### Черновики КП и исходы

Знаменатель конверсии — уникальные допустимые черновики, созданные в выбранном окне;
числитель — отправленные из них предложения. Открытые черновики должны быть полными
и актуальными; неполные и устаревшие исключаются явно. Последующие сделки связываются
с происхождением черновика без второго независимого окна. Компания видит свою активность.

Бизнес-отказ, ошибка модели, блокировка допуска, Human Approval Guard и запрет замещения
учитываются отдельно. Повтор отказа дедуплицируется; старые незаписанные блокировки
неизвестны. Неизвестные длительность и затраты — null с показателем покрытия.
Репутационные отзывы и индекс исполнения — разные показатели.
