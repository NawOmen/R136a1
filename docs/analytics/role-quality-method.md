# Методика оценки агентных ролей (версия role-quality-1)

Оценка — только по сохранённым событиям, без ручных чисел. Итоговый балл не вводится:
аспекты не компенсируют друг друга, нарушение полномочий не покрывается скоростью или
дешевизной. Сравниваются только сопоставимые модельные роли (`buyer_agent`, `seller_agent`).
Кодовые роли (подбор, коалиции, устойчивость) оцениваются конверсиями scorecard и
проверками допуска.

## Источники

- `agents.agent_runs` (журнал LLM Gateway): тип роли, состояние, ошибка, длительность,
  стоимость, версии модели и промпта, структурированный результат.
- `agents.tool_calls`: подтверждённые уточняющие диалоги (`apply_user_clarification`).
- `marketplace.offer_drafts.changed_fields`: существенные исправления человека (роль продавца).
- `marketplace.trust_audit_events`: заблокированные действия (соблюдение полномочий).
- Эталон: `packages/test-fixtures/agent-task-bank/ru_tasks.json` — русскоязычные задачи
  с `expected_category` и `critical_fields`.

## Правила

- Окно: `window_days` (1–365, по умолчанию 30). Когорта — прогоны, созданные в окне.
- Минимум наблюдений на роль: 5. Меньше — статус «Не оценено», метрики — пусто.
- Успешный сценарий: состояние не `failed` и ошибки нет.
- Полнота критичных полей (`buyer_agent`): доля свойств результата со статусом
  `confirmed` среди всех свойств. У `seller_agent` свойств нет — поле пустое.
- Конфликты: число найденных противоречий в результатах выборки.
- Диалоги: доля прогонов с подтверждённым уточнением.
- Исправления человека: число изменённых полей использованных черновиков (продавец).
- Время и стоимость: среднее время; сумма известных оценок + доля известных.
  Неизвестная стоимость — не ноль, а пусто с указанием покрытия.
- Человеко-время напрямую не измеряется: прокси — число подтверждений человека
  (scorecard) и исправлений; это неполная мера, а не учёт часов.
- Версии: различные `model_version`/`prompt_version` в выборке (S12.05: модель/маршрут/версия).
- Эталон применяется периодическими точечными проверками задач банка вне рантайма:
  автоматическое сопоставление прогонов с банком не выполняется, потому что входная
  сводка прогона не содержит полного текста для надёжного matching. Эндпоинт
  сообщает доступность банка (`benchmark.available`) и число задач.

## Эндпоинты

- `GET /companies/{company_id}/role-quality` — участник компании (покупка или продажа).
- `GET /platform/role-quality` — администратор маркетплейса.
