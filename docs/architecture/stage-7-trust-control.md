# Этап 7: доверие, контроль и KPI

Критичные действия проходят два слоя: проверку актуального JWT и полномочий компании, затем явное решение пользователя. Выбор предложения, подтверждение плана устойчивости, резерва и восстановления создают `HumanApprovalRecord`; LLM не вызывает эти операции напрямую.

`TrustAuditEvent` образует последовательную SHA-256-цепочку. В хеш входят предыдущее значение, тип и субъект события, актор, источники, объяснение, payload и время. PostgreSQL advisory lock сериализует добавление. Проверка цепочки доступна администратору; API не предоставляет изменение и удаление событий. Хеш-цепочка обнаруживает подмену, но не заменяет внешнее неизменяемое хранилище для production.

KPI рассчитываются при запросе из событий: GMV и сделки, человеческие подтверждения, подтверждённая резервная мощность, восстановления и разница с зафиксированной базовой конфигурацией. Нулевое значение означает отсутствие подтверждённых событий, а не вручную заданный результат.

Запуски LLM хранят длительность, объём входа/выхода и оценочную стоимость локального инференса. Тариф `LOCAL_INFERENCE_COST_RUB_PER_MINUTE` — настраиваемая эксплуатационная оценка в рублях, не счёт провайдера. Внешний маршрут не получает выдуманную стоимость.

Негативные границы: загруженный документ получает только `unverified`; инструкции внутри источников считаются недоверенными данными; отсутствие цены отклоняет схема; истёкшее удержание резерва не считается подтверждённым и запрещает автоматическое восстановление.
