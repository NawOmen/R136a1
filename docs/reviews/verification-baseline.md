## Что исправлено

### Категория и подкатегория потребности

В форме появился обязательный выбор подкатегории в существующем оформлении. Он сохраняется вместе с черновиком, сбрасывается при смене категории/компании и восстанавливается при повторном открытии. Подтверждённый результат агента заполняет распознанную подкатегорию; если агент указал только общий уровень, пользователь выбирает вид товара сам.

`Need` и контракты `/api/v1/needs` дополнены необязательным `subcategory`; родительское поле `category` сохранено. Миграция marketplace `0020` добавляет nullable-колонку без переписывания существующих запросов. Старые клиенты с точным названием в `category` продолжают работать. Отсутствующее новое поле не меняет старый хеш идемпотентности.

Подкатегория учитывается при совместимости товара, проверке допуска к прямой и групповой сделке, резерву и замене поставщика, в аудиторском снимке и при уведомлении об изменении документа. Повторный заказ сохраняет её. Несовпадающие подкатегории не объединяются в одну коалицию, а родительские производственные категории и единицы мощности сохраняются. Хеши старых групп без подкатегории не меняются.

Каталог и область применения документов разделены: принадлежность к ветке каталога не расширяет проверенную область сертификата. Известная подкатегория без отдельного регуляторного профиля получает прежний явный статус `not_configured`, как запрос с точным названием в старом API. Это **не подтверждение соответствия** и не объявление всех категорий полностью проработанными. Неизвестные подкатегории регулируемых веток, неподдерживаемая медицина и отсутствующие обязательные документы остаются блокирующими. Версия правил — `categories-3`.

### Лента подходящих запросов продавца

Фильтр учитывает категорию и подкатегорию товара, точные старые названия и нормализацию регистра/`ё`. Показываются подходящие запросы общего уровня и нужной подкатегории. Другая подкатегория, чужое семейство, закрытые и просроченные запросы исключаются. Проверка права продавца и обезличенный контракт сохранены. Отсутствие товаров сохраняет прежний путь открытой ленты для работы по паспорту возможностей.

### Пользователи администратора

В новом синтетическом наполнении используется валидный `supplier@demo.ru`. Все seed-адреса проходят тот же `EmailStr`, что и API.

Миграция auth `0004` исправляет только старую запись `supplier@porukam.test` с её известным детерминированным UUID. Пароль, UUID и членство в компаниях сохраняются; обычные аккаунты не переименовываются. При конфликте с другим владельцем нового адреса миграция останавливается с объяснением и не объединяет аккаунты. Downgrade не возвращает недопустимый email.

Проверено обновление уже существующей БД тестового стенда: прежний поставщик сохранил UUID `b0c9b34d-7b69-53fa-a005-b953b6464f4a`, адрес стал валидным. Затем браузерный набор выполнен на отдельном свежем синтетическом наполнении. Backend-регрессии проверяют выдачу всех seeded-пользователей, повторный seed, сохранение членства/пароля и безопасную обработку коллизии.

### Запуск MinIO

Основной Compose собирает образ по `infra/minio/Dockerfile`, без ранее недоступного registry-образа и без временного override. Источник — официальный фиксированный коммит, архив проверяется по SHA-256. Версия обозначена `SOURCE`, с upstream commit-id; LICENSE и соответствующий исходный архив включены в контейнер. Это сборка проекта, не официальный release-бинарник. [Происхождение, сборка и исходники](../../infra/minio/README.md).

Полный стандартный стенд из восьми контейнеров успешно запущен; миграции проверены на старой и свежей БД. Наличие исходников и успешный S3-тест не заменяют проверку условий конкретного распространения AGPL.

### Зависимости

- PyJWT: минимум 2.15.0, зафиксирована 2.15.1 в трёх затронутых сервисах.
- urllib3: минимум и lock 2.8.0 для транспорта MinIO. Это уже существовавшая транзитивная зависимость; прямое ограничение предотвращает возврат уязвимой версии.
- source-map-js: override и lock 1.2.2 для цепочки Next/PostCSS.
- Python locks пересобраны с хешами под фактический Python 3.12, с сохранением остальных зафиксированных версий. Изменение не добавляет новый фреймворк или внешний сервис.

Повторные `pip-audit` всех четырёх lock-файлов и `pnpm audit --prod --audit-level=moderate` не обнаружили известных уязвимостей. Это результат advisory-баз для этих зависимостей, а не гарантия отсутствия любых уязвимостей приложения или всех базовых Docker-образов.
