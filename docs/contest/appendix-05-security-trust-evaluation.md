# Приложение 5. Безопасность, доверие, контроль и оценка эффективности агентов

> Приложение к презентации «ПоРукам» (Приложение 1 положения: «механизмы безопасности, доверия, контроля и оценки эффективности агентов»). Закрывает критерий «Инновационность и концепция среды ИИ-агентов» в части оценки работы агентов.

## 1. Безопасность

| Механизм | Что сделано | Где в проекте |
|---|---|---|
| Обязательные секреты | `JWT_SECRET`, `OPTIMIZER_TOKEN`, пароль MinIO обязательны, проверяются при старте, минимум 48 символов и не менее 16 уникальных; секретов в репозитории нет | `services/*/app/config.py`, `scripts/init-local-env.py`, `docs/security/hardening.md` |
| Единая точка вызова модели | внешние и локальные модели вызываются только через LLM Gateway; ключи не хранятся в коде | `services/llm-gateway/` |
| Обезличивание контекста | в модель уходят «Покупатель B», «Производитель A», «товар категории X» без контактов, реквизитов и файлов клиента | `docs/architecture/stage-4-agents.md` |
| Разграничение доступа | права по членству в компании; администратор площадки — отдельный признак; проверяющий документов — только администратор площадки | `services/marketplace/app/deps.py` |

| Ограничение поверхности | сервисы слушают `127.0.0.1`, наружу открыт только edge; HTTPS с проверкой сертификата | `infra/docker-compose.yml`, `infra/docker-compose.https.yml` |
| Целостность зависимостей | пакеты ставятся по хешам из `requirements.lock` | `.github/workflows/ci.yml`, `services/*/requirements.lock` |

## 2. Доверие

- **Проверка компании отдельно от проверки документов.** Компания может быть верифицирована, но товар без подтверждённых документов не публикуется и сделка не создаётся.
- **Применимость документа проверяет человек.** Документ без области действия не считается доказательством; проверяющий фиксирует подтверждённые материал и покрытие, а расхождение значений блокирует.
- **Покупатель видит чек-лист.** В карточке товара показано, какие требования подтверждены, со ссылкой на регламент и без внутренних данных документов.
- **Отзывы только по подтверждённым сделкам.** Рейтинг компании формируется после отметки о получении.
- **Открытость границ.** В интерфейсе и документах прямо указано, что площадка не перевозчик, не платёжный агент и не выдаёт юридических заключений.

## 3. Контроль действий агентов

| Контроль | Как работает |
|---|---|
| Human Approval Guard | обязательные действия фиксируются с решением человека: подтверждение цены и объёма, допуск документов, выбор предложения, подтверждение резерва и замены |
| Хеш-цепочка журнала | каждое событие содержит ссылку на предыдущее и хеш содержимого; подмена записи обнаруживается проверкой цепочки |
| Запреты для модели | LLM не назначает цену, мощность, резерв и не меняет статус сделки; эти значения приходят только из данных продавца и расчётов |
| Блокировка действий | публикация товара, сделка, групповое обязательство, резерв и замена блокируются при неподтверждённых доказательствах, с объяснением на русском языке |
| Прозрачность источников | каждое поле черновика КП сопровождается источником; поля без данных помечаются как «решение человека» |
| Устойчивость к отказу модели | Seller Agent поддерживает rules_only, необязательный внешний review может пропускаться. Сбой обязательного локального извлечения требований завершает задачу failed/503; продолжение с сохранённым вводом входит в C08 |

Журнал решений доступен администратору площадки, а проверка целостности цепочки встроена в интерфейс (`/trust` или раздел администратора).

## 4. Оценка эффективности агентов

Показатели считаются из журналов, а не вписываются вручную. Панель доступна в кабинете («Проверяемые KPI»), администратор площадки видит значения по всей площадке.

| Группа | Показатель | Смысл |
|---|---|---|
| Черновики КП | сформировано черновиков | объём автоматизации |
| | отправлено после проверки человеком | конверсия сценария «черновик → предложение» |
| | конверсия, % | доля черновиков, дошедших до предложения |
| | среднее число правок человеком | качество предложенных значений: чем меньше правок, тем точнее агент |
| | сделок из черновиков | влияние на результат, а не на активность |
| Контроль человека | подтверждений человека | сколько обязательств прошло через человека |
| | заблокированных действий | сколько раз система остановила недопустимое действие |
| | проверок допуска и остановок на допуске | работа механизма доказательств |
| Рекомендации | конверсия рекомендаций в предложения | полезность ленты рыночных возможностей |
| Модель | запусков агентов, отказов, маршрут (локальный или внешний), средняя длительность, оценочная стоимость инференса | стоимость и надёжность агентной части |

Отсутствие данных не подменяется нулями: если журнал вызовов модели недоступен, панель прямо сообщает об этом.

**Панель оценки агента (scorecard)** возвращает отдельные показатели: конверсию сценария, правки человеком, отказы модели и оценочную стоимость. Итоговый вычисляемый рейтинг агента в текущем обработчике не найден. Методика сравнения по одинаковым задачам, категориям, версиям и полноте данных входит в C15; она пока не реализованный рейтинг. Рейтинг компании-производителя формируется отдельно — по отзывам после подтверждённых сделок.

## 5. Как проверяющий убеждается в честности показателей

1. Показатели считаются запросами к таблицам и журналу, а не хранятся готовыми числами.
2. Журнал защищён хеш-цепочкой: изменение прошлой записи ломает проверку.
3. Хеш-цепочка выявляет нарушение связности сохранённого журнала, но без независимого якоря не доказывает невозможность полной переписи администратором с доступом к данным. Не описывать её как неизменяемое внешнее доказательство.
4. В панели указано окно расчёта (по умолчанию 30 дней) и перечислены причины отсутствия данных.
5. Синтетические расчёты в презентации помечаются как результаты тестового сценария, а не как показатели промышленной эксплуатации.

## 6. Ограничения

- Прототип не проходил пентест; документ `docs/security/hardening.md` не является сертификатом безопасности.
- Реальные реквизиты, персональные данные и клиентские документы в демонстрации не используются.
- Юридические формы в интерфейсе — маркированные макеты, требующие проверки юристом.
- Сверка с государственными реестрами и проверка подлинности документов не реализованы: проверяющий работает с загруженными файлами.
