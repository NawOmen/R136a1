# Сценарий технической демонстрации (code review)

> Подготовка к п. 7.2.1 положения RLT.StartUp: организатор вправе запросить онлайн-встречу, на которой команда показывает работу системы и при необходимости отдельные фрагменты кода **демонстрацией экрана**. Передача кода, копий и доступ к репозиторию не требуются и не предоставляются.

## 1. Что показываем

| Блок | Что демонстрируем | Ориентир по времени |
|---|---|---|
| Карта системы | сервисы, схемы данных, кто с кем общается | 3 минуты |
| Живой сценарий | запрос → черновик КП → допуск → сделка → резерв | 7 минут |
| Границы модели | где LLM вызывается и где запрещено менять цену, мощность, резерв, статус сделки | 3 минуты |
| Доказательства | журнал аудита, хеш-цепочка, решения человека | 3 минуты |
| Код | 2–3 фрагмента по вопросам: черновик КП, проверка допуска, контроль человека | 4 минуты |

## 2. Порядок показа

1. Открыть схему: `docs/contest/appendix-03-architecture-and-roles.md` (и архитектурная схема команды, если подготовлена).
2. Запустить локальный стенд: `docker compose --env-file .env -f infra/docker-compose.yml up -d` и открыть интерфейс.
3. Показать вход продавца: лента запросов → «Подготовить черновик КП» → значения с источниками и пометками «решение человека».
4. Показать проверку допуска: отозвать подтверждение документа у проверяющего и показать, что сделка блокируется с объяснением.
5. Показать сделку и таймлайн подтверждений этапов.
6. Показать панель оценки агентов: конверсия черновиков, правки человека, отказы модели, стоимость.
7. Перейти к коду по вопросам организатора.

## 4. Ответы на ожидаемые вопросы

- **Почему цена не назначается моделью?** Цена — обязательство; она берётся из данных продавца (каталог, ступени) и подтверждается человеком. В промптах агентов цена, мощность, резерв и статус сделки прямо запрещены к изменению.
- **Что будет, если модель недоступна?** Шаг выполняется на правилах, интерфейс сообщает режим работы; сценарий не останавливается.
- **Как проверяется корректность данных?** Каждое существенное поле имеет источник; при отсутствии данных поле помечается как пробел и требует решения человека.
- **Где доказательства неизменности решений?** Журнал событий с хеш-цепочкой: изменение прошлой записи обнаруживается проверкой.
- **Какие тесты есть?** pytest по каждому сервису, API-регрессия Playwright, проверка русского интерфейса, миграции на чистой базе (см. `.github/workflows/ci.yml`).
- **Есть ли ограничения прототипа?** Да, перечислены в `docs/contest/submission-requirements.md` и приложениях: нет сверки с реестрами, нет платежей и юридических заключений.

## 5. Что не показываем и не передаём

- исходный и объектный код в виде файлов и архивов;
- доступ к репозиторию, системам контроля версий и среде разработки;
- `.env`, ключи, сертификаты, персональные данные и реальные реквизиты;
- данные реальных компаний: демонстрация идёт только на синтетических данных.
