# Сценарий технической демонстрации (code review)

> Подготовка к п. 7.2.1 положения RLT.StartUp: организатор может запросить онлайн-технический показ системы, архитектуры, модулей и при необходимости фрагментов кода. Показ проводится демонстрацией экрана; обязательная передача кода, копий или доступа к репозиторию из этого пункта не следует — [сверка положения](../../NEXT_STEPS.md#stage-19).

Это сценарий будущей репетиции/показа, а не запись уже проведённой встречи. [S17](stage-17-evidence.md) содержит текущие доказательства; [S18](../../NEXT_STEPS.md#stage-18) — материалы защиты. Лимит до 20 минут относится к защите по Приложению 1; указанное ниже распределение — ориентир команды.

## 1. Что показываем

| Блок | Конкретный результат | Ориентир |
|---|---|---|
| Карта системы | реальные сервисы, данные, локальная модель и отключённые интеграции | 3 минуты |
| Связанный сценарий | потребность → источник → правка КП → согласие → исполнение | 7 минут |
| Отказ/восстановление | одна блокировка, её причина, исправление на новой версии | 3 минуты |
| Контроль/метрики | роль человека, происхождение обязательства, исходы и покрытие оценки | 3 минуты |
| Фрагменты кода и вопросы | черновик, допуск, task-contract/guard по запросу | 4 минуты |

Использовать синтетическую российскую компанию и один из 46 сквозно проверенных на синтетике рабочих листьев [S15](../../NEXT_STEPS.md#stage-15). Категории из меню не объявляются автоматически прошедшими полный маршрут.

## 2. Подготовка стенда

1. Зафиксировать commit, версии образов/моделей и данные. Подготовить кеш, env и локальные артефакты по [инструкции S15](../operations/stage-15.md); секреты хранить вне Git и экрана.
2. На выделенном синтетическом стенде проверить вход обеих ролей, каталог, Gateway и незавершённую задачу. Исторический результат на M1 не заменяет новый прогон.
3. Если используется второе устройство, проверить его доверенный HTTPS, адрес/CORS и закрытые служебные порты. Отдельно проверить физическую запись микрофона; загрузка аудиофайла — предусмотренный путь при отказе разрешения.
4. Подготовить разрешённые экраны с исходными данными, без env, токенов и приватных файлов. Использовать сохранённый безопасный материал резерва, когда он будет подготовлен в S18.
5. До встречи зафиксировать ожидаемые статусы/суммы/ресурсный эффект выбранного случая; не выдавать незавершённый или skipped тест за успех.

Backup/restore и restart выполняются только на отдельном подготовленном стенде по [S15](../operations/stage-15.md). Этот документ не является поручением менять рабочую среду во время встречи.

## 3. Порядок показа

1. Открыть [реальную архитектуру](appendix-03-architecture-and-roles.md); назвать LLM-шаг, обычный расчёт и решение человека.
2. Показать потребность, источник существенного поля, пробел/конфликт и подтверждение покупателем.
3. В кабинете продавца подготовить КП: цена из каталога, объём из актуального ресурса, неизвестная логистика. Изменить поле, показать preview/diff и отправить.
4. В отдельном синтетическом случае показать неподтверждённое доказательство: guard блокирует обязательство с причиной. Исправить условие, не обходя guard.
5. Создать допустимое обязательство с явным согласием и показать замороженные условия. Подтвердить приёмку; повторить допустимую операцию и показать отсутствие второго эффекта.
6. Открыть аналитику/scorecard: заказано и исполнено отдельно, платежи/затраты с полнотой, конверсия с знаменателем. Для роли показать исходный результат и экспертный эталон либо «Не оценено».
7. Показать версию задачи, состояние и ограниченный путь восстановления. Резерв демонстрировать только при подтверждённом актуальном ресурсе; непокрытие сохранять.
8. Перейти к фрагментам кода по вопросам организатора.

Доказательства операций и ограничения: [сценарии](appendix-02-agent-interaction-scenarios.md), [автоматизация](appendix-04-automation-demo.md), [S17](stage-17-evidence.md). Сквозная трасса с подставным ответом LLM доказывает связность контрактов, но не является новым живым измерением модели.

## 5. Краткие ответы с границами

- **Почему модель не назначает цену?** Цена и ресурс берутся из актуальных данных и расчётов, а обязательство требует согласия человека; [черновик](../../services/marketplace/app/offer_draft.py), [guard](../../services/marketplace/app/trust.py).
- **Что происходит без модели?** Обязательное извлечение даёт `failed`/503 с повтором/ручным путём. Seller Agent может использовать `rules_only`, необязательный внешний review пропускается. Универсального продолжения без модели нет; [Gateway](../../services/llm-gateway/app/api.py).
- **Почему данным можно доверять?** Источник и версия позволяют проверить утверждение; конфликт/неизвестное требует уточнения. Правильность ответа проверяется сравнением с экспертным эталоном, а не только наличием источника; [role-quality-2](../analytics/role-quality-method.md).
- **Журнал неизменяемый?** Hash-chain проверяет связность сохранённых записей. Независимого внешнего якоря нет; полная перепись привилегированным администратором не исключена; [контроль](appendix-05-security-trust-evaluation.md).
- **Есть готовый рейтинг агента?** Есть отдельные метрики и реализованная методика качества; общего рейтинга нет. При недостаточной сопоставимой выборке — «Не оценено»; [методика](../analytics/role-quality-method.md).
- **Где доказательство экономии и прибыли?** S16 содержит заданные расчётные случаи с отрицательными и неизвестными исходами. Реальная экономия не измерена; прибыль ограничена известными сопоставимыми затратами, GMV не доход; [S16](../analysis/stage-16.md).
- **Что уходит во внешнюю модель?** В опциональном review — четыре ограниченных счётчика, при явном разрешении; оригиналы и значения фактов не входят. Regex не гарантирует полной анонимизации; [S14](../architecture/stage-14-integrations.md).
- **Какие проверки уже были?** Исторические программные/живые результаты и оборудование указаны в [S15](../../NEXT_STEPS.md#stage-15); текущий срез — в [S17](stage-17-evidence.md). Физический микрофон и HTTPS второго устройства не заменяются mock.
- **Работают реестр, ЭДО и оплаты?** ЭДО/реестр/логистика имеют честный `not_connected`; банковский расчёт, подписанный документ и государственная проверка не заявлены. Версионированный CSV-обмен действует отдельно; [S14](../architecture/stage-14-integrations.md).

## 6. Безопасная поверхность показа

На экран выводятся разрешённые синтетические данные, рабочие артефакты и выбранные фрагменты кода. Исходники в архиве и доступ к репозиторию не входят в предусмотренный технический показ. Env, ключи, сертификатные приватные ключи, персональные данные и реальные реквизиты не показываются — [правовые требования конкурса](../../NEXT_STEPS.md#stage-19), [S15](../operations/stage-15.md).

Готовность видео, резервного материала и самой репетиции фиксируется по факту в [S18](../../NEXT_STEPS.md#stage-18); наличие этого сценария не закрывает их.
